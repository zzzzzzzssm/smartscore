# 语音返回首页覆盖全部模式设计

## 问题

语音命令“返回首页”沿用早期页面白名单，只认识首页、选谱、练习准备、谱面、结果和设置页面。后来新增的其它模式中心、节拍器、校准音和音符识别监测均由 `screen_modes` 私有管理，因此会被判定为当前页面无法执行；创作者模式则被原逻辑显式拒绝。

## 设计

- 保留 `screen_adapter` 作为语音命令统一入口，命令 ID 和 ACK 流程不变。
- 在 `screen_modes` 增加仅供 LVGL 线程调用的返回首页处理函数，由它识别自己持有的页面并执行页面专属清理。
- 在处理旧的练习页面白名单前，先让 `screen_modes` 尝试处理；未命中时继续执行原练习导航逻辑。
- 其它模式中心直接返回首页。
- 节拍器页返回前停止节拍器，防止语音焦点释放后恢复播放。
- 校准音页返回前停止校准音。
- WAV 播放页返回前停止文件播放，并清除选谱页的返回覆盖回调。
- 音符识别监测页返回前停止 Audio S3 监测会话。
- 创作者设置页直接返回首页；创作进行中按现有“退出”语义取消未保存录制，然后返回首页。保存仍只由“保存乐谱”触发。
- 首页及原练习、选谱、结果和设置页面继续走现有逻辑，不改变评分收尾行为。

## 方案取舍

继续扩大 `screen_adapter` 的固定页面白名单改动较小，但会泄漏其它模式的私有页面和资源清理细节。全局页面注册表扩展性最好，但对当前七条本地命令过重。由页面所有者处理识别和清理、语音入口只负责编排，边界清晰且改动集中，因此采用该方案。

## 静态验证

- 确认其它模式中心、节拍器、校准音、WAV 播放、音符识别监测和创作者页面均有命中路径。
- 确认每个带后台资源的页面在跳转前执行对应停止操作。
- 确认普通选谱页不会被误判为 WAV 播放页。
- 确认未命中其它模式时仍进入原练习页面返回逻辑。
- 确认命令成功返回 `true`，使 Voice S3 收到成功 ACK。
- 按要求不执行固件编译。

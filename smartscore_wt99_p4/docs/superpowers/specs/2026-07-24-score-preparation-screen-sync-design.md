# 乐谱准备页与屏幕跟谱同步设计

## 目标

修复小程序选谱流程与设备屏幕流程不一致的问题。小程序选择乐谱后，设备屏幕应自动进入同一乐谱的准备页；简谱/五线谱、只读看谱/演奏跟谱和输入源由设备端统一保存，并在小程序与屏幕之间双向同步。任意一端点击开始后，设备屏幕进入对应的乐谱显示或实时跟谱页面。

本次同时恢复本机扬声器的真实硬件输出。此前完成的音量、节拍器、标准音和 WAV 播放状态同步继续保留。

## 范围

本次修改仅包括：

- 设备端乐谱准备会话及对应 API。
- 屏幕选谱、准备页、乐谱显示和跟谱流程的远程驱动与状态回读。
- 小程序乐谱选择后的准备界面及双向同步。
- 恢复 WT99 本机扬声器初始化和真实声音输出。
- 与上述功能直接相关的测试和构建配置。

本次不修改三个 S3 项目，不实现新的 S3 功能，不重构评分算法、乐谱解析器或其它小程序页面。

## 方案选择

采用“设备端统一准备会话”方案。设备端是当前待演奏乐谱和准备选项的唯一状态源；屏幕与小程序都是该状态的客户端。

不采用直接模拟 LVGL 按钮的方案，因为它依赖具体控件结构，UI 更新后容易失效。也不采用仅在开始时让屏幕显示乐谱的方案，因为那无法让准备页和选项真正双向同步。

## 设备端准备会话

新增一个边界清晰的准备会话，保存：

- 当前乐谱来源和安全文件名。
- 标题、BPM、拍号等只读摘要。
- `notation_type`：`numbered` 或 `staff`。
- `mode`：`read_only` 或 `follow`。
- `input_source`：`usb_midi` 或 `audio_s3`。
- 当前阶段：`idle`、`prepared`、`starting`、`reading`、`following`、`error`。
- 单调递增的修订号，用于屏幕和小程序判断状态是否变化。
- 最近一次错误及面向用户的错误说明。

会话内部负责校验选项组合、序列化状态和协调屏幕跳转，不让 HTTP 处理函数直接操作具体 LVGL 控件。

## API

在保留现有乐谱文件列表和文件读取接口的基础上，补充统一准备接口：

- `GET /api/practice/preparation`
  - 返回当前乐谱摘要、准备选项、阶段、修订号和错误。
- `POST /api/practice/preparation/select`
  - 参数：安全的 SD 乐谱文件名。
  - 加载并校验乐谱，初始化默认选项，并请求屏幕进入准备页。
- `POST /api/practice/preparation/options`
  - 参数可包含 `notation_type`、`mode`、`input_source`。
  - 原子校验并更新选项，修订号加一。
- `POST /api/practice/preparation/start`
  - 使用当前统一选项开始只读看谱或演奏跟谱。

现有 `/api/scores/sd/select` 保持兼容，但内部转到统一选谱逻辑。现有 `/api/start` 保持兼容，并使用当前准备会话；没有有效准备会话时仍按原有“已载入评分乐谱”规则处理，避免破坏既有调用方。

## 屏幕交互

### 小程序发起选谱

1. 小程序调用统一选谱接口。
2. 设备读取并校验 SD 乐谱。
3. 设备建立准备会话。
4. 在 LVGL 上下文内打开该乐谱的准备页。
5. 准备页显示乐谱标题、BPM、拍号及当前选项。

### 屏幕发起选谱

屏幕原有“演奏”入口继续打开准备页，同时写入同一准备会话。小程序轮询准备状态后显示同一乐谱和同一选项。

### 选项同步

- 屏幕点击简谱、五线谱或输入源时，先更新准备会话，再刷新屏幕选中状态。
- 小程序提交选项时，准备会话更新修订号；屏幕定时器发现修订号变化后刷新控件。
- 小程序轮询同一状态接口，因此屏幕改动也会反映到小程序。
- 用户正在操作某个控件时，不用轮询值覆盖当前触摸过程；提交后以设备返回状态为准。

准备页新增只读看谱/演奏跟谱选择。只读看谱不要求评分输入源在线；演奏跟谱必须通过现有输入源和连接状态校验。

## 开始行为

### 只读看谱

- 使用选择的简谱或五线谱渲染完整乐谱。
- 屏幕进入现有乐谱显示页。
- 不启动评分服务，不锁定输入源。
- 保留屏幕返回选谱页的能力。

### 演奏跟谱

- 使用选择的简谱或五线谱渲染乐谱。
- 选择并锁定输入源。
- 启动评分服务和实时跟谱。
- 屏幕进入现有音乐显示页并显示结束演奏控件。
- 小程序状态同步为正在跟谱。

无论由屏幕还是小程序开始，都调用同一个设备端开始函数，避免两条实现路径出现行为差异。

## 小程序

小程序在选择有效乐谱后进入准备界面，而不是仅显示“已选择”：

- 显示标题、BPM、拍号。
- 提供简谱/五线谱选择。
- 提供只读看谱/演奏跟谱选择。
- 演奏跟谱时显示 USB MIDI/麦克风输入选择。
- 显示设备屏幕是否已进入准备页以及当前阶段。
- “开始”按钮调用统一开始接口，成功后进入练习状态页。

小程序继续保存乐谱的本地副本用于列表和结果图表，但设备端准备会话是远程操作的权威状态。

## 扬声器恢复

- 打开 `CONFIG_SMARTSCORE_SPEAKER_ENABLED`。
- 启动时恢复 `speaker_service_init()`、ES8311、I2S 和功放控制。
- 不再为正常构建调用无声控制模式。
- 保留此前实现的统一音频状态及双向同步。
- 音量继续遵守设备硬件的 0–80 限制，小程序继续显示为 0–100。
- 若音频硬件初始化失败，乐谱只读和无节拍器的跟谱仍可使用；音频接口返回明确硬件错误，不伪装为无声测试模式。

## 线程与页面安全

HTTP 请求运行在服务线程，不能直接修改 LVGL 对象。远程选谱、选项更新和开始请求通过屏幕适配层投递到 LVGL 上下文，并在显示锁保护下执行页面创建、控件刷新和页面切换。

准备会话的状态访问使用互斥保护。较慢的文件读取和 JSON 解析不在 LVGL 锁内执行。

## 错误处理

- 无效或不存在的乐谱文件：选谱失败，屏幕保持原页面。
- 乐谱没有有效音符：不建立准备会话。
- 屏幕尚未就绪：返回冲突错误，不报告选择成功。
- 只读渲染失败：阶段进入 `error`，不进入乐谱页。
- 跟谱启动失败：解除已取得的资源和输入锁，阶段进入 `error`。
- 输入源未连接：只阻止演奏跟谱，不阻止只读看谱。
- 扬声器初始化失败：音频功能显示硬件错误，不阻止不依赖声音的乐谱显示。

屏幕和小程序都显示设备端返回的同一错误说明。

## 验证

### 设备端

- 选谱后准备会话字段和默认选项正确。
- 简谱/五线谱、只读/跟谱和输入源更新均增加修订号。
- 屏幕选项更新可通过 API 回读。
- API 更新后屏幕控件刷新。
- 只读模式进入乐谱页但不启动评分。
- 跟谱模式进入乐谱页并启动评分。
- 非法文件、无音符、屏幕未就绪和输入断开返回明确错误。

### 小程序

- 选谱后进入准备界面。
- 准备选项请求字段与设备接口一致。
- 设备端状态变化能回写到小程序。
- 只读模式不要求输入源连接。
- 跟谱模式按设备返回结果进入练习状态。

### 构建与硬件

- 运行全部小程序 JavaScript 语法检查和既有测试。
- 增加准备状态同步测试。
- 使用 ESP-IDF 5.5.3 全量构建 WT99 固件。
- 确认构建配置中扬声器已启用。
- 实机验证屏幕选谱、小程序选谱、双向切换、只读显示、实时跟谱以及真实扬声器输出。

## 完成标准

- 小程序选择乐谱后，屏幕自动显示同一乐谱准备页。
- 两端的简谱/五线谱、只读/跟谱和输入源一致。
- 任意一端开始都让屏幕显示正确记谱类型，并进入正确模式。
- 只读模式不启动评分；跟谱模式正常启动评分和实时显示。
- 扬声器真实输出恢复，音频控制仍能双向同步。
- 不修改三个 S3 项目或其它无关功能。

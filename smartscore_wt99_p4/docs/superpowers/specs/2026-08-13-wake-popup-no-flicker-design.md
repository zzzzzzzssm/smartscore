# 语音弹窗与启动音量设计

## 目标

语音唤醒后不再显示“正在聆听…\n请说出指令”弹窗，避免 WAKE 事件触发 LVGL 顶层重绘和屏幕闪动。提示音继续作为唤醒反馈，本地命令执行结果弹窗继续保留。设备每次启动时将扬声器初始音量统一设置为 80%。AI 单轮唤醒状态机和其他页面逻辑保持不变。

## 方案选择

采用“唤醒只给音频反馈，命令结果复用预创建弹窗”方案：

- 不转发 `SCREEN_VOICE_EVENT_WAKE`，因此唤醒时不执行任何弹窗显示或顶层重排。
- 不关闭本地命令执行结果弹窗，避免失去命令成功/失败反馈。
- 命令结果继续使用现有 `lv_layer_top()` 弹窗，在屏幕初始化阶段创建一次并隐藏，之后仅更新内容和隐藏标志。

## 组件与数据流

1. `screen_adapter` 初始化 UI 后，在已持有显示锁的情况下调用 `ensure_voice_popup()`，创建命令反馈弹窗并保持隐藏。
2. P4 收到 `S3_VOICE_EVENT_WAKE` 后继续获取扬声器焦点并播放提示音，但不向 `screen_adapter` 转发 WAKE 弹窗事件。
3. 收到本地命令结果时，LVGL 异步回调更新已有弹窗的颜色和文字，然后清除 `LV_OBJ_FLAG_HIDDEN`。不重新创建对象，不调用 `lv_obj_move_to_index()`。
4. 命令结果弹窗使用一个长期复用的 LVGL timer。每次显示只更新周期、复位并恢复 timer；超时后隐藏弹窗并暂停 timer。
5. 本地命令执行与 ACK 流程不变。

## 启动音量

- 将板级 `BOARD_WT99_AUDIO_INITIAL_VOLUME_PERCENT` 从 15 调整为 80；系统现有最大音量也是 80。
- 不在 `app_main` 中追加异步调音量命令，避免启动阶段先以旧音量初始化、随后突然跳变。
- `board_audio`、`speaker_service` 状态和设置页面滑块都继续读取同一个板级初始值，因此启动显示与实际硬件音量保持一致。
- 本次不增加 NVS 音量持久化；每次重新启动都回到 80%，启动后用户仍可在设置页面向下调节。

## 并发与错误处理

- 所有 LVGL 对象操作仍通过现有 `lv_async_call()` 在 LVGL 上下文执行。
- 启动阶段预创建失败时保留现有空指针检查，不影响语音、扬声器或其他 UI 启动。
- timer 创建失败时弹窗仍可显示，并由后续 TIMEOUT/COMMAND 事件关闭；不阻塞语音任务。
- 不新增任务、队列或长期内存缓存。

## 验收

- 说出唤醒词后只听到提示音，不显示“正在聆听”弹窗，也不触发整屏闪白或页面重载。
- 多次唤醒不创建、显示或重排任何顶层弹窗。
- 本地命令执行结果仍正常显示，并复用同一个弹窗和 timer。
- AI 回答结束后仍执行约 192 ms AFE 清理，并且下一轮必须重新说唤醒词。
- 每次设备启动后，扬声器硬件状态和设置页面音量均为 80%。
- 不修改评分、MIDI、识谱、建议、Wi-Fi/BLE、扬声器 ring 或模型配置。

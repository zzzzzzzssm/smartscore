# 豆包全双工实时语音助手设计

## 边界

现有唤醒、MultiNet 本地命令、UI 动作、识谱、评分和练习建议均保持原样。
新功能只旁路 AFE 音频并在 P4 新增实时语音会话；所有网络、JSON、Base64
和播放工作都运行在独立任务或既有扬声器任务中。

## 方案选择

原 UART 115200 无法承载 16 kHz s16le 原始 PCM（256 kbit/s）。提高波特率
会改变既有板间参数；Base64 文本帧开销也超出链路容量。因此选择独立块的
4-bit IMA-ADPCM，在保留原 UART、引脚和文本命令协议的同时把音频降到约
64 kbit/s。每块自带预测器状态，允许单帧校验和重传。

## 分流与状态

S3 检测到唤醒后开始旁路音频，但继续执行原 MultiNet。P4 先缓存候选 PCM：
本地命令命中时清空缓存；原 6 秒超时发生时，S3 仍发送 `V1,TIMEOUT` 供旧
UI 收尾，再发送 `V2,AI,BEGIN`。之后 S3 连续流送，直到 P4 因退出意图或
致命错误发送 `V2,AI,STOP`，S3 才恢复等待唤醒。

## 豆包协议与播放

P4 使用官方新版 `X-Api-Key` WebSocket 和 JSON 文本事件：输入 16 kHz PCM，
输出 24 kHz `pcm_s16le`，模型固定 `1.2.6.1`。扬声器服务新增有界 PCM
StreamBuffer，仍由原扬声器任务独占板级音频输出。ASR 开始事件触发本地
播放中断与 `response.cancel`。断线由 WebSocket 客户端自动重连，会话重建
后继续发送有界输入环形缓冲中的音频。

## 配置与扩展

Key 仅从构建环境变量 `DOUBAO_VOICE_API_KEY` 注入私有目标定义。音色、提示
词、缓冲和重连参数位于独立 Kconfig。只读 context provider 为以后提供当前
曲目和最近评分摘要预留，不依赖或修改现有评分服务。

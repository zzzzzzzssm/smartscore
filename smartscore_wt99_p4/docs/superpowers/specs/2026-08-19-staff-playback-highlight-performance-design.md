# 五线谱播放高亮性能优化设计

## 背景

本地乐谱只读预览已经支持根据 JSON 合成钢琴音、显示当前音符并自动翻页。当前五线谱高亮切换时会调用 `lv_obj_invalidate()` 使整张五线谱画布重新绘制。画布重绘需要遍历全部谱面元素，并重新绘制谱线、符号和贝塞尔曲线；播放回调还会约每 40 毫秒重复更新状态文字和检查翻页，因此设备屏幕出现明显卡顿。

简谱不在本次优化范围内。声音生成、播放速度、练习结果颜色以及同曲重练清理逻辑保持不变。

## 目标

- 五线谱播放时，高亮切换不触发整页乐谱重绘。
- 高亮仍以扬声器实际播放位置为基准，优先保证声音与画面同步。
- 支持单音及和弦高亮。
- 暂停时保留高亮，继续后从原位置恢复。
- 播放结束或退出预览时清除高亮并回到第一页。
- 自动翻页保持正常，但不阻塞逐音符高亮。

## 方案选择

采用独立高亮覆盖层。

未选择仅降低刷新频率，因为它仍会整页重绘，并会以增加高亮延迟换取有限的改善。未选择整页位图缓存，因为它会明显增加 PSRAM 占用，并扩大翻页和练习颜色更新的改造范围。

## 架构

### 乐谱主体

五线谱画布继续负责静态谱面和练习结果颜色。播放高亮不再在画布的主绘制回调中渲染，也不再因为高亮变化而使画布失效。

### 高亮区域缓存

乐谱完成排版后，为每个音符事件计算一次高亮矩形，并缓存为画布局部坐标。一个 MIDI 音符索引通过现有 `note_event_indices` 映射到排版事件；同一事件关联的短谱线和符号共同确定矩形边界。共享长横梁不计入边界，避免高亮跨越整段乐句。

乐谱重新排版、内容变化或显示对象销毁时重建缓存。普通播放进度变化不重新计算几何位置。

### 独立覆盖层

在五线谱画布上方维护固定数量的半透明蓝色矩形对象。覆盖层对象不参与滚动布局，只使用缓存坐标更新位置和尺寸，并跟随画布父级滚动。

单音显示一个矩形。和弦可能对应多个排版事件，因此显示多个矩形；对象数量设置明确上限，超过上限时合并为覆盖整个和弦的包围矩形，避免动态分配和对象数量失控。

高亮切换只执行以下操作：

1. 隐藏上一个音符组不再使用的矩形。
2. 将需要显示的矩形移动到缓存位置并更新尺寸。
3. 显示新的矩形并将其保持在谱面符号之下或使用低透明度，确保音符清晰可读。

此流程不调用五线谱画布的整页失效接口。

## 播放刷新流程

播放器继续根据扬声器 `played_bytes` 计算当前播放样本和音符组。只有音符组变化时才更新五线谱高亮。

屏幕适配层记录上一次播放器状态、音符范围和翻页检查时间：

- 播放状态文字仅在状态发生变化时更新。
- 当前音符或和弦范围仅在范围变化时更新。
- 自动翻页约每 100 毫秒检查一次，与高亮更新解耦。
- 准备阶段不显示高亮；扬声器实际开始输出后才进入播放状态。
- 暂停事件立即保留当前覆盖层位置；继续事件不重建覆盖层。
- 停止、播放完成、错误或退出预览时隐藏覆盖层并复位页面。

播放器状态通知仍可保持现有周期，以免改变音频时间基准；屏幕层负责消除重复 UI 操作。

## 错误处理

- 某个音符没有有效排版事件或缓存区域时，只跳过该音符的高亮，不中断音频播放。
- 覆盖层对象创建失败时，记录错误并退化为无高亮播放；不得恢复到高频整页重绘。
- 翻页期间缓存坐标保持不变，因为坐标相对整张可滚动画布；页面滚动只改变可视区域。
- 新乐谱加载时必须先隐藏旧覆盖层并重建缓存，避免显示上一首曲子的高亮。

## 验证

本次按用户要求不执行固件编译。代码修改后进行静态检查，确认：

- 高亮切换路径不再调用五线谱画布整页失效。
- 重复播放状态不会反复修改 LVGL 标签。
- 音符组变化仍立即更新高亮。
- 自动翻页检查被限频，但不会影响音符高亮频率。
- 单音、和弦、暂停、继续、播放完成、手动退出和切换乐谱均有对应的清理路径。

硬件上的最终验收标准是：播放五线谱时无可见整页闪烁或明显卡顿，高亮与钢琴声音保持同步。

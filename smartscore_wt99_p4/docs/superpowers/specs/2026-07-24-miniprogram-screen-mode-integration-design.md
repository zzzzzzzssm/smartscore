# 小程序与屏幕模式联动设计

## 背景

以用户提供的 `SmartMusic (2).zip` 为屏幕端行为参考。该压缩包的
`main` 分支指向提交 `2fdab7f6450cb39e262b48f3ade2bc584edab168`，其中“其他模式”
包含：

- 创作者模式：USB MIDI 实时录制、暂停/继续、结束并保存到 SD 卡；
- 节拍器模式；
- 校准音模式；
- 读取 `/sdcard/wav` 的本地音乐播放模式。

当前工作区的小程序已经能够控制节拍器、校准音和 SD 卡 WAV 播放，但没有创作者
模式入口，也不能列出或选择设备 SD 卡中的乐谱。现有乐谱页使用示例数据初始化，
练习页把评分放在操作按钮之前，首页则使用一张完整卡片作为“连接设备”入口。

本设计将新增真实的设备接口和小程序页面，使屏幕与小程序共用同一套创作者和乐谱
状态。压缩包只作为当前屏幕行为与能力的参考，不整体覆盖当前工作区，也不导入其中
的 `.git`、构建产物或无关依赖。

## 已确认的产品决策

1. “手机本地”指小程序自己的持久化乐谱库，不要求访问手机任意目录。
2. 创作者模式必须支持完整远程控制：配置、开始、暂停、继续、结束保存和实时状态。
3. 删除源码和已有缓存中可明确识别的示例数据，保留所有用户数据。
4. SD 卡乐谱被选择后直接加载为设备当前乐谱；只有用户点击“保存到本地”时才下载
   到小程序本地库。
5. 练习页采用独立的“操作优先”布局，不与创作者页面合并。
6. 首页基本保留现有横幅、两列卡片、最近练习和底部导航。把“连接设备”改为
   “核心功能”标题右侧的小按钮，原卡片位置改为“创作者模式”。
7. 本次只记录尚未在小程序实现的屏幕能力，不扩展到创作者选区重弹、谱面渲染切换、
   屏幕亮度或开发诊断入口。

## 目标

- 乐谱页提供“上传文件”“设备 SD 卡”“手机本地”三个清晰的数据来源。
- 小程序能够列出、加载和按需保存 `/sdcard/scores` 中的有效 JSON 乐谱。
- 小程序和屏幕能够控制并观察同一个创作者会话。
- 练习页先显示操作，再显示模式相关的实时状态和过程图谱，最后显示评分。
- 删除所有小程序示例乐谱、示例记录、示例结果和示例设备状态。
- 轻量整理“我的”页面，不引入账号、社区或云同步等无关能力。
- 保持现有练习评分、输入源、节拍器、校准音、WAV 播放和设备连接流程可用。

## 非目标

- 访问微信沙箱之外的手机任意文件目录。
- 在小程序中渲染可点击的五线谱或简谱。
- 远程执行创作者“按小节选区重弹覆盖”。
- 远程调整屏幕亮度。
- 把屏幕动画测试等开发诊断入口暴露给普通用户。
- 重写现有评分算法、MIDI 解析器、音频 S3 协议或扬声器实现。
- 整体解压或合并 `SmartMusic (2).zip`。

## 总体架构

采用薄 HTTP 接口加共享设备状态的方案：

```text
小程序页面
  ├─ 乐谱库
  ├─ 创作者
  ├─ 练习
  └─ 我的
       │
       ▼
device_api
  ├─ SD 乐谱列表 / 选择 / 下载
  ├─ 创作者状态 / 开始 / 动作
  └─ 既有练习、输入、音频接口
       │
       ▼
共享设备服务
  ├─ score_storage + score_data
  ├─ creator_mode + creator_recorder
  ├─ scoring_service
  └─ speaker_service
```

小程序不实现第二套创作者状态机。`creator_mode` 的屏幕按钮和远程命令调用相同的
内部操作函数；`screen_adapter` 暴露线程安全的创作者和 SD 乐谱适配接口；
`device_api` 只负责参数校验、冲突检测和 JSON 编解码。

HTTP 线程不能直接无锁修改 LVGL 对象。共享创作者状态使用互斥保护；需要更新屏幕
控件时使用既有显示锁。USB MIDI 事件仍由当前唯一消费者分发，不增加第二个队列
消费者。

## 设备接口

### SD 乐谱列表

`GET /api/scores/sd?page=1&page_size=20&search=`

成功响应：

```json
{
  "ok": true,
  "sd_present": true,
  "directory": "/sdcard/scores",
  "page": 1,
  "page_size": 20,
  "total": 2,
  "items": [
    {
      "filename": "CR000012.JSON",
      "title": "创作乐谱 12",
      "bpm": 100,
      "time_signature": "4/4",
      "note_count": 48,
      "measure_count": 8,
      "file_size": 8320
    }
  ]
}
```

列表只扫描 `/sdcard/scores`，不返回屏幕端内置测试乐谱或 SPIFFS 条目。文件扩展名
大小写不敏感，但仅接受 `.json`。`page_size` 有固定上限，搜索只匹配文件名和标题。

### 选择 SD 乐谱

`POST /api/scores/sd/select`

请求体：

```json
{"filename":"CR000012.JSON"}
```

设备读取并使用当前 JSON 解析器校验乐谱，然后替换 `score_data` 中的当前乐谱。
成功响应返回标题、BPM、音符数和文件名。解析失败不能覆盖原当前乐谱。

### 保存 SD 乐谱到小程序

`GET /api/scores/sd/file?name=CR000012.JSON`

成功时以 `application/json` 返回原乐谱 JSON。该接口只允许安全的单层文件名，拒绝
绝对路径、`..`、目录分隔符、非 JSON 扩展名和超过 256 KiB 的文件。

### 创作者状态

`GET /api/creator/status`

响应字段：

```json
{
  "ok": true,
  "available": true,
  "state": "idle",
  "waiting_first_note": false,
  "bpm": 100,
  "time_sig_num": 4,
  "time_sig_den": 4,
  "staff_mode": "grand",
  "note_count": 0,
  "measure_count": 0,
  "usb_midi_connected": true,
  "saved_title": "",
  "saved_filename": "",
  "message": "ready"
}
```

`state` 只使用 `idle`、`recording`、`paused`、`saving` 和 `error`。等待首音通过
`waiting_first_note` 表示，不额外制造一个录制器状态。

### 开始创作

`POST /api/creator/start`

请求体：

```json
{
  "bpm": 100,
  "time_sig_num": 4,
  "time_sig_den": 4,
  "staff_mode": "grand"
}
```

合法范围与屏幕选项一致：BPM 为 60、80、100 或 120；拍号为 2/4、3/4、4/4
或 6/8；声部为 `single` 或 `grand`。练习正在录制或评分时返回 `409 Conflict`。

### 创作者动作

`POST /api/creator/action`

请求体：

```json
{"action":"pause"}
```

`action` 只接受：

- `pause`：从录制进入暂停并发布当前快照；
- `resume`：从暂停进入等待首音/继续录制；
- `finish`：只允许在暂停状态保存到 `/sdcard/scores`；
- `cancel`：停止并丢弃未保存会话。

成功响应使用与状态接口相同的字段。`finish` 额外返回 `saved_title` 和
`saved_filename`。合法的重复命令返回当前状态，非法状态转换返回 `409 Conflict`
且不修改会话。

### 模式互斥

- `/api/creator/start` 在练习录制或评分期间拒绝执行。
- `/api/start` 和屏幕练习入口在创作者非空闲时拒绝执行。
- 屏幕创作者按钮和小程序命令使用同一检查。
- 手机网络断开不结束创作者会话；USB MIDI 断开沿用现有行为，自动暂停。

## 小程序本地乐谱库

乐谱索引保存在微信同步存储中，实际规范化 JSON 写入
`wx.env.USER_DATA_PATH/scores/`。索引项包含：

```js
{
  id,
  title,
  composer,
  bpm,
  noteCount,
  updatedAt,
  source,
  localFilePath,
  deviceFilename
}
```

- JSON 上传：校验后复制到用户目录并建立索引。
- MIDI 上传：沿用现有客户端解析器，转换为规范化 JSON 后写入用户目录。
- 图片上传：保留现有压缩、设备上传和 AI 识谱流程；只有识别出有效音符后才写入
  本地乐谱库。
- SD 保存到本地：下载 JSON、再次校验并建立本地索引。
- 创作者结束：文件先保存在设备 SD 卡；结果页提供“保存到本地”，不自动复制。
- 删除本地乐谱：同时删除索引和对应用户文件；不能删除设备 SD 卡原文件。

导入成功即进入手机本地库。“上传文件”标签负责导入动作，“手机本地”标签负责
浏览和选择已经持久化的乐谱。

## 示例数据迁移

删除 `utils/mock.js` 及其初始化依赖。首次运行新版本时执行一次迁移：

- 删除 ID 为 `score_twinkle`、`score_ode`、`score_scale_c` 的乐谱；
- 删除 ID 为 `record_20260525_1`、`record_20260524_1` 的练习记录；
- 删除来源明确为 `本地示例` 的条目；
- 清除示例练习结果和示例设备状态；

- 写入迁移版本标记，后续启动不重复扫描。

空库、空记录和空统计都显示真实空状态，不重新填充示例。

## 页面设计

### 首页

保留现有：

- 渐变横幅、头像、标题和标签；
- “核心功能”标题；
- 两列六卡片布局；
- 最近一次练习；
- 底部五项导航。

改动：

- 在“核心功能”标题右侧增加小型“连接设备”按钮；
- 按钮显示灰色未连接或绿色已连接状态点；
- 删除原“连接设备”大卡片；
- 原位置改为“创作者模式”卡片；
- 其余五张卡片的位置和用途保持不变。

### 乐谱页

页面顶部使用三个页内标签：

1. 上传文件；
2. 设备 SD 卡；
3. 手机本地。

上传标签保留 JSON/MIDI、图片、AI 识谱和屏幕上传能力。SD 标签提供连接提示、刷新、
分页列表、加载到设备、保存到本地和开始练习。手机本地标签提供选择并同步、重命名
和删除。页面不再显示“先使用本地数据，后续可接设备”等示例性说明。

### 创作者页

创作者使用独立页面，包含：

- USB MIDI 和设备连接状态；
- BPM 四个预设；
- 四种拍号；
- 单声部/双声部；
- 开始创作；
- 录制中的暂停和取消；
- 暂停后的继续、结束保存和取消；
- 状态、音符数、小节数和提示；
- 保存成功后的 SD 文件名及“保存到本地”。

页面每秒刷新设备状态。页面被隐藏时停止轮询；再次显示时先读取设备状态，不重置
设备会话。

### 练习页

顺序调整为：

1. 当前乐谱和状态；
2. 开始练习、结束并评分、AI 建议、重新练习；
3. 评分输入源；
4. 设备实时状态；
5. 演奏过程图谱；
6. 总分、音准、节奏和完整度。

USB MIDI 模式只显示 MIDI 连接、当前音、已识别/目标和阶段。音频 S3 模式只有在
接口已实现时才显示节点连接、RMS、噪声和阈值；未实现时显示明确说明，不显示无意义
的占位数值。

### 我的

保留头像、昵称、练习统计和现有帮助入口，做轻量间距、卡片和空统计调整。增加
“我的设备”入口，复用设备页面。没有真实记录时显示 `0` 和 `—`，不显示示例分数。

## 错误处理

- 未连接设备：上传和手机本地仍可使用；SD 与创作者显示连接设备操作。
- 未插 SD 卡：显示独立空状态，不影响本地乐谱库。
- SD 目录为空：显示 `/sdcard/scores` 中暂无乐谱。
- 文件损坏：显示具体文件名和解析失败，不替换当前乐谱。
- 文件过大：客户端和设备端都拒绝超过 256 KiB 的 JSON。
- 本地文件名冲突：使用内部唯一 ID 和唯一文件名，展示标题可重复。
- 本地存储失败：保留设备当前乐谱，并提示用户清理小程序存储后重试。
- 手机断线：创作者继续在设备运行，重连后恢复状态。
- USB MIDI 断线：创作者自动暂停并提示重新连接。
- 模式冲突：返回 `409` 和当前占用模式，页面提供前往对应页面的入口。
- 保存失败：创作者保持暂停状态，允许检查 SD 卡后再次结束保存或取消。

## 屏幕能力差异审计

本次完成后，小程序将覆盖屏幕的创作者、节拍器、校准音和 SD WAV 播放模式。
以下能力仍只保留在屏幕：

- 创作者通过谱面选择小节范围并重弹覆盖；
- 五线谱/简谱显示切换和只读谱面浏览；
- 屏幕亮度调整；
- 动画测试和其他开发诊断入口。

这些差异在交付说明中列出，但不作为本次缺陷。

## 验证

### 自动检查

- 对所有小程序 JavaScript 运行语法检查。
- 为本地乐谱索引、示例迁移和设备状态规范化增加纯 JavaScript 测试。
- 为创作者合法/非法状态转换、重复命令和 USB 断连增加组件测试。
- 为 SD 文件名校验、只列 SD、分页、损坏文件和 256 KiB 上限增加测试。
- 运行现有协议测试及固件完整编译。

### 小程序开发工具

- 空数据首次启动没有示例。
- 上传 JSON/MIDI 后出现在手机本地。
- 三个乐谱来源可独立切换并保持正确空状态。
- 首页保持原视觉结构，连接设备按钮位于标题右侧。
- 练习操作位于评分之前，评分在图谱之后。
- 页面隐藏后停止轮询，重新进入后恢复真实设备状态。

### 真机回归

- 插卡、未插卡、空目录和损坏 SD 乐谱。
- SD 乐谱加载、开始练习和保存到手机本地。
- 屏幕开始创作后小程序接管暂停/继续/保存。
- 小程序开始创作后屏幕显示同一会话。
- USB MIDI 断开自动暂停，重连后可继续。
- 手机 Wi-Fi 中断后设备录制继续，重连状态恢复。
- 创作者和练习的双向互斥。
- 既有节拍器、校准音、WAV 播放、练习评分和设备配网回归。

## 完成标准

- 小程序不再包含或恢复任何示例乐谱、记录、结果或设备状态。
- 三种乐谱来源均有真实、可验证的数据流。
- SD 卡选择和保存本地均通过真机测试。
- 屏幕和小程序对创作者状态、音符数和保存结果保持一致。
- 首页、练习页和“我的”页符合已确认的布局。
- 固件构建通过，现有核心功能无回归。

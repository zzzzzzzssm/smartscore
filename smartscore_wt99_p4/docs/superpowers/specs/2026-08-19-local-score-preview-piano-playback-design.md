# 本地乐谱预览钢琴播放与同谱重练清理设计

## 目标

在 WT99 设备屏幕的“只读看谱”页面加入单按钮播放控制。设备根据当前本地乐谱 JSON 的音高、开始时间和时值实时合成钢琴感 PCM，并让谱面高亮当前正在播放的音符；和弦整体高亮，跨页时自动翻页。

同时修复重复练习同一首乐谱时保留上一轮跟谱颜色和引导的问题。每一轮练习都必须从无反馈状态开始，无论乐谱内容是否变化。

## 范围

本次包括：

- WT99 设备屏幕“只读看谱”页面的播放、暂停和继续按钮。
- 从当前乐谱 JSON 构建播放时间线。
- 设备端轻量多音钢琴合成与 PCM 输出。
- 当前音符/和弦高亮、按播放时间自动翻页和结束回第一页。
- 页面退出、切换记谱方式、换谱和音源抢占时的可靠清理。
- 每次开始练习前无条件清空上一轮简谱和五线谱反馈。

本次不包括：

- 小程序端的乐谱播放或跟谱动画。
- 真实钢琴多采样资源、SoundFont、效果器或可选音色。
- 播放进度拖动、变速、循环、逐段播放或独立停止按钮。
- 改变评分算法、实时匹配规则或练习结果计算。
- 修改三个 S3 项目的业务功能。

## 已确认的用户交互

播放功能只在 `SCREEN_PREPARATION_READING` 对应的“只读看谱”页面显示。

页面顶部在“返回”和“切换简谱/五线谱”右侧增加一个按钮：

- 初始为“播放”；
- 播放中为“暂停”；
- 暂停后为“继续”；
- 正常播完、被抢占或失败后恢复为“播放”。

按钮使用一个控件切换状态，不增加独立停止按钮。点击“返回”或切换简谱/五线谱时，先停止乐谱播放、清除当前音符高亮，再执行原有操作。切换记谱方式不会保留播放位置。

播放开始时从第一音符和第一页开始。暂停时保留当前页与当前音符高亮。播放结束时清除高亮、回到第一页并恢复“播放”按钮。

## 方案选择

采用设备端轻量多音钢琴合成方案。

不采用真实钢琴采样，因为当前工程没有可复用的钢琴采样文件，新增多采样会显著增加 Flash 或 SD 资源、资源授权和移调混音复杂度。不采用现有单音正弦接口，因为它不能可靠表现和弦，音色也不符合钢琴播放预期。

合成器使用少量泛音、快速起音、自然衰减和短释放包络生成“钢琴感”音色。它不承诺录音级真实钢琴音质，但必须清楚区分不同音高、支持常见和弦并避免明显爆音。

## 组件边界

### 乐谱播放控制器

新增独立的乐谱播放控制器，负责：

- 接收当前 JSON、预览 BPM 和播放代次；
- 构建并持有不可变播放时间线；
- 管理 `stopped`、`playing`、`paused`、`finishing` 和 `error` 状态；
- 生成固定大小的 24 kHz、16-bit、单声道 PCM 块；
- 根据扬声器实际消费的样本数计算播放位置；
- 发布当前音符分组、播放时间、结束和错误通知；
- 在停止或换代时释放时间线、合成声部和 PCM 状态。

控制器不创建或直接操作 LVGL 对象，也不负责解析页面手势。

### 扬声器服务

现有 `speaker_service` 继续是唯一硬件播放入口。乐谱控制器通过 PCM 流接口输出，不直接调用 I2S 或板级 Codec。

PCM 流补充显式暂停和继续语义：

- 暂停停止硬件继续消费，但保留尚未播放的环形缓冲和已播放样本计数；
- 生产者在暂停状态不继续生成，避免缓冲被提前填满；
- 继续时重新打开硬件输出并从原位置消费；
- 停止或抢占时丢弃该流的剩余数据。

任何新的主音源仍按现有规则替换旧主音源。乐谱控制器必须检测流已被其它音源中止，并将自身状态转为 `stopped`，不得自动恢复。

### 乐谱显示

`music_display` 负责：

- 创建和刷新只读页面播放按钮；
- 接收控制器状态并更新“播放/暂停/继续”文字；
- 使用现有期望音符引导绘制当前音符分组；
- 使用现有按乐谱时间翻页逻辑自动翻页；
- 提供回到第一页、清空当前引导和清空全部练习反馈的显式接口。

音频合成、时间线推进和扬声器状态不放入 `music_display`。

### 屏幕适配层

`screen_adapter` 协调页面生命周期：

- 只读乐谱成功显示后绑定当前 JSON 和预览 BPM；
- 播放按钮回调转发给乐谱播放控制器；
- 返回、切换记谱方式、加载新谱和离开只读模式前停止播放；
- 每次开始练习前调用完整反馈清理，再启动评分和实时跟谱；
- 将控制器通知安全地应用到 LVGL 页面。

## 播放时间线

当前本地乐谱 JSON 的扁平 `notes` 数组是显示和评分兼容层已经使用的数据源。每个有效音符至少包含：

- `midi`：0 到 127；
- `start` 或等价的 `start_tick`；
- `duration` 或等价的 `duration_ticks`；
- 可选的 `staff` 和 `voice`。

时间线构建使用与当前预览相同的 BPM 规则，把所有音符归一为 `midi`、`start_ms`、`duration_ms`，然后按开始时间、谱表、声部和音高稳定排序。无效音符被拒绝；若没有任何可播放音符，则整次播放失败并保留只读页面。

开始时间相同的连续音符组成一个高亮分组。这样单音高亮一个音符，和弦同时高亮全部成员。显示槽位使用同一排序规则，避免声音事件与谱面音符错位。

休止不生成声部；相邻音符之间的时间差自然产生静音。

## 钢琴合成

输出格式固定为现有实时 PCM 链路支持的 24 kHz、16-bit、单声道。

每个声部保存 MIDI 音高、相位、开始/结束样本、包络阶段和泛音状态。基频按标准十二平均律从 MIDI 音高计算。每个样本使用有限数量的泛音叠加，并应用快速起音、主体衰减和短释放包络。

并发声部数量固定且有上限，内存不会随乐谱长度增长。达到上限时优先替换包络电平最低且最接近结束的声部。时间线上保留全部音符，只有实际同时发声的合成声部受限。

混音根据当前活跃声部数缩放，并在写入 `int16_t` 前进行限幅，避免和弦叠加产生整数溢出或明显削波。音符结束后允许短释放尾音，但释放不得改变下一音符的时间线或高亮时刻。

## 音画同步与自动翻页

PCM 生产位置不能作为可见播放位置，因为环形缓冲会预先生成音频。播放控制器以 `speaker_service` 报告的实际已消费 PCM 字节数换算播放毫秒数，并以此驱动高亮和翻页。

在每次播放时钟更新时：

1. 找出当前开始时间已经到达且仍处于显示时值内的音符分组；
2. 用 1-based 包含范围更新现有蓝色期望音符引导；
3. 将当前乐谱时间交给现有自动翻页函数；
4. 只有分组变化时刷新音符引导，避免无意义的 LVGL 重绘。

五线谱继续使用浅蓝半透明框和蓝色边框；简谱继续使用蓝色文字与下划线。播放高亮不写入正确、部分正确、错误或漏音状态。

暂停冻结已消费样本时钟并保留当前高亮。继续后从同一样本位置推进。正常播放结束后，等待短释放尾音和扬声器排空，再清除引导并回到第一页。

## 同谱重练反馈清理

当前问题的根因是：虽然新一轮解析时会重置 `s_note_status`，五线谱视图发现新旧 MIDI 内容完全相同时会跳过场景重建，场景对象里上一轮写入的颜色因此仍然保留。仅清空状态数组不足以恢复画面。

新增显式、幂等的完整反馈清理操作，并在每次练习启动前无条件调用。它同时完成：

- 将全部简谱音符状态恢复为未知状态；
- 将五线谱场景内所有事件颜色恢复为默认颜色；
- 清除当前期望音符/播放音符引导；
- 刷新当前简谱 span 和五线谱画布；
- 将页面回到第一页；
- 清除显示层内部与上轮结果相关的索引或缓存状态。

清理不依赖文件名、JSON 哈希、MIDI 内容是否变化或是否重新布局。即使用户连续多次练习同一首谱，每次开始时也必须得到黑色默认谱面和新的首音引导。

该清理只清除显示反馈，不删除上一轮评分结果记录，也不改变当前所选乐谱。

## 状态与并发

每次开始播放分配单调递增的播放代次。停止、换谱、切换记谱方式和页面退出都会增加代次。工作任务或回调携带旧代次时，其高亮、翻页、完成和错误通知全部被忽略。

播放控制器状态由互斥或命令队列保护。LVGL 对象只在显示锁保护的上下文中修改；较慢的 JSON 解析和 PCM 生成不持有显示锁。

按钮快速连点必须保持可预测：

- `playing` 时点击只提交一次暂停；
- `paused` 时点击只提交一次继续；
- `stopped` 或播放完成后点击创建新代次并从头播放；
- `finishing` 状态拒绝重复开始，待清理后恢复为 `stopped`。

## 音频焦点与页面生命周期

点击乐谱“播放”沿用现有主音源替换规则，会停止当前节拍器、WAV 或其它普通主音源。若语音助手或其它更晚的音源抢占扬声器，乐谱播放立即结束、清除高亮并恢复按钮，不自动继续。

以下事件必须停止乐谱播放：

- 点击只读页面“返回”；
- 切换简谱/五线谱；
- 加载或选择另一首乐谱；
- 从只读模式进入练习跟谱、创作者模式、其它播放模式或首页；
- 扬声器流失败或被抢占。

停止操作幂等。页面销毁或已经离开时，迟到通知不得访问失效 LVGL 对象。

## 错误处理

- JSON 无效、BPM 非法或没有有效音符：不启动 PCM，状态栏显示乐谱不可播放，按钮恢复为“播放”。
- 内存或任务创建失败：释放已分配时间线和声部，保留只读谱面。
- 扬声器未初始化或硬件输出失败：显示明确的扬声器错误，只读翻页继续可用。
- PCM 流背压：生产任务保留未接受的 PCM 尾部并重试，不跳过时间线；长期失败则结束本次播放。
- 音源被替换：作为正常停止处理，不显示误导性的硬件故障。
- UI 更新失败或页面已离开：音频必须仍能停止并释放，不能依赖 UI 回调完成资源清理。

## 验证

### 单元和组件测试

- MIDI 音高到基频的映射、包络阶段和释放结束。
- 单音、和弦、休止、重叠长音和超出声部上限的确定性处理。
- 混音输出不发生整数溢出，静音区间为零或允许的极低尾音。
- JSON 时间线排序、BPM 换算、无效音符和空乐谱错误。
- 播放、暂停、继续、正常完成、显式停止和音源抢占状态转换。
- 以已消费 PCM 样本数驱动高亮，而不是已生成样本数。
- 播放代次能屏蔽停止后的迟到通知。

### 显示回归

- 播放按钮只在只读看谱页面显示，文字按状态切换。
- 简谱当前音符为蓝色下划线，五线谱当前事件显示浅蓝框。
- 同一开始时间的和弦整体高亮。
- 多页乐谱随播放时间自动翻页，暂停不翻页，结束回第一页。
- 返回、切换记谱方式和换谱后没有残留声音、高亮或迟到翻页。

### 同谱重练回归

分别在简谱和五线谱下完成一轮产生正确、部分正确、错误和漏音颜色的练习，然后不换谱直接重新开始：

- 开始前所有旧颜色恢复默认；
- 上一轮蓝色引导被清除；
- 新一轮只显示当前首个目标分组；
- 上一轮评分结果仍保留在结果记录中；
- 连续第三次开始仍得到相同干净状态。

### 构建与实机

- 运行相关组件测试和既有回归测试。
- 执行 WT99 ESP-IDF 完整构建。
- 实机确认单音与常见和弦音高可辨、无明显爆音。
- 实机确认暂停/继续没有跳音或时间漂移，音符高亮与听感同步。
- 实机确认语音或其它音源抢占后不会自动恢复乐谱播放。

## 完成标准

- 只读看谱页面可用单个按钮从头播放、暂停和继续当前 JSON 乐谱。
- 设备输出稳定的多音钢琴感 PCM，支持常见和弦和休止。
- 当前音符/和弦高亮与实际扬声器播放位置同步，并能自动翻页。
- 播放结束、页面退出、切谱、切换记谱方式或音源抢占后没有残留音频与 UI 状态。
- 连续练习同一首乐谱时，上一轮跟谱颜色和引导在新一轮开始前全部清除。
- 不破坏现有评分、小程序、创作者模式、节拍器、WAV 和语音播放流程。

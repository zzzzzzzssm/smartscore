# SmartScore 跟谱引导与 Audio S3 音符监视设计

## 目标与边界

本次仅修改 P4 设备端显示接入：

1. 跟谱练习时，在演奏发生前突出显示下一个应演奏的音或同一时刻的和弦。
2. 在“其他模式”右下角增加一个轻量的“音符识别测试”入口，显示 Audio S3 已经上报的单音与和弦。

不修改 Audio S3 串口协议、评分规则、输入源选择、现有模式布局、小程序、语音助手、MIDI、识谱或练习建议。

## 方案

### 下一音符引导

`screen_adapter` 继续作为跟谱状态的唯一所有者。它从当前 `s_aligned_index` 开始，找到尚未消费的第一个音符，并把相同 `start_ms` 的音符视为一个待演奏组。待演奏组变化后，仅把首尾索引通知 `music_display`。

- 五线谱：`leland_score_view` 汇总同一音符事件关联的音头、符干、符尾、升降号、附点和连线范围，在所有乐谱元素之前绘制浅蓝色圆角引导框。框的宽度按实际音符范围加边距，高度统一为 128 px，并以完整事件边界的中线对齐；这样不同音高、符干方向和时值的引导框视觉高度一致且能覆盖整个音符，而不只覆盖音头下部。色块是独立绘制层，不改变音符本身颜色。
- 简谱：对应数字使用蓝色强调；一旦原有演奏结果到达，绿、黄、红、灰状态色优先。
- 会话结束时清除引导；开始、匹配音符和超时跳过音符时刷新引导。

这样不改变现有匹配、计分和翻页逻辑，也不会把“待演奏”误表示成“已弹正确”。

### 音符识别测试模式

在现有四个模式卡片之外，单独在“其他模式”页面右下角增加小入口，不重新排列原 UI。

进入页面后通过 `audio_s3_adapter_start_session()` 启动现有 Audio S3 音乐流；退出时停止。`main` 收到的 `s3_music_event_t` 仍照常送往评分和跟谱，同时额外送一份给 `screen_modes`。

Audio S3 回调运行在非 LVGL 任务，因此回调只在短临界区内更新固定大小快照，不创建对象、不调用 LVGL、不等待队列。现有 250 ms UI 定时器读取快照并更新测试页。

- 单个 NOTE_ON 显示例如 `C4`。
- P4 为 Audio S3 已有 `poly` JSON 增加完整解析，读取 `kind`、`notes[2..4]`、可选 `name` 和 `confidence`，并作为一个原子监视事件分发。测试页优先直接显示该双音或和弦，避免多音数据在 P4 被静默丢弃。
- `poly` 只进入设备测试页，不转换成评分使用的多个 NOTE_ON；Audio S3 原有旋律 NOTE_ON 仍按原路径进入评分，因此不产生重复音符或改变跟谱结果。
- 对没有 `poly` 的旧固件，约 300 ms 内到达的多个 NOTE_ON 仍可作为兼容兜底合并显示；不猜测和弦性质，保证音符列表与串口 MIDI 数据一致。
- 同时显示 MIDI、频率和置信度（字段存在时）。
- 最近结果短暂保持，避免 NOTE_OFF 后立即闪烁消失。

## 并发与错误处理

- Audio S3 事件入口不得触碰 LVGL；共享快照使用极短自旋锁保护。
- `poly` 数组限制为 2 至 4 个合法 MIDI 值，字段非法时按现有协议错误计数丢弃，不允许越界或部分事件进入 UI。
- 页面创建失败或 Audio S3 启动失败时，只在测试页显示错误，不影响其他模式。
- 离开测试页始终停止本页启动的 Audio S3 session，并清理快照。
- 不新增后台任务和大缓存，不占用现有语音、扬声器或评分内存预算。

## 验收要点

- 跟谱开始即突出第一个待演奏音；弹奏或超时后引导移动到下一组，同一时刻和弦同时突出。
- 原有演奏结果颜色、评分、翻页和输入源行为不变。
- “其他模式”原四张卡片位置不变，右下角出现“音符识别测试”。
- 测试页能显示 Audio S3 串口对应的 MIDI 单音与近同时音符组合，退出后不再占用 Audio S3 音乐流。

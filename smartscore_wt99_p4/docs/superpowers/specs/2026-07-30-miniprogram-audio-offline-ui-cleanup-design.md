# 小程序音频页面离线界面清理设计

## 目标

“节拍器与校准音”和“音乐播放模式”在设备未连接时继续显示完整的正常操作界面，不再出现“离线预览模式”卡片、引导按钮或连接后才可使用等专属说明。页面顶部仍如实显示设备未连接状态；用户触发任何依赖设备的操作时，统一提示“设备未连接”，且不发送设备请求。

## 方案

采用最小状态清理方案，保留现有页面结构、状态轮询和设备命令入口，不伪造在线状态，也不抽取新的跨页面连接层。

- 页面顶部的连接圆点与状态文字继续使用真实的 `online` 状态。
- 删除两个页面中仅在离线时出现的提示卡、说明文字和“前往设备页”按钮。
- 页面主体不再根据 `online` 切换为“离线预览”“连接后可播放”或“连接后读取 SD 卡”等文案，而是始终使用正常操作界面的中性说明。
- 未连接且没有曲库数据时，音乐页使用与在线空曲库一致的中性空状态，不伪造 SD 卡已就绪或虚构文件。
- 不改变扬声器禁用的 `controlOnly` 提示；该状态表示设备已经在线但硬件输出被禁用，不属于离线预览内容。

## 交互行为

无需设备的本地选项继续即时生效，包括 BPM、拍号、BPM 输入和校准音时长。

以下依赖设备的操作在 `online` 为假时统一显示“设备未连接”，立即结束且不调用 API：

- 音量调整、静音和停止声音；
- 开始、暂停和停止节拍器；
- 播放校准音；
- 音乐搜索、清空后重新读取、刷新、上一页和下一页；
- 音乐播放、暂停和停止。

已连接时维持现有请求、状态同步、播放替换和错误处理行为。设备从在线变为离线时，顶部显示真实连接错误；页面主体保持正常布局，不重新出现离线预览内容。

## 文案

- 未配置设备地址时，顶部状态使用“设备未连接”。
- 已配置但设备暂时不可达时，保留现有真实连接错误文案。
- 所有离线设备操作的 Toast 固定为“设备未连接”。
- 删除“离线预览”“离线参数预览”“连接设备后可播放”“连接设备后读取 SD 卡”等页面主体文案。

## 验证

自动化测试需要覆盖：

1. 两个 WXML 页面不再包含“离线预览”卡片及连接后使用的说明。
2. 未连接时仍可调整 BPM、拍号和校准音时长。
3. 未连接时，各类设备依赖操作均显示“设备未连接”。
4. 被拦截的操作不调用音频状态、控制或文件列表 API。
5. 首页与设备页的现有入口仍可进入两个音频页面。
6. 已连接状态的既有音频接口与状态同步测试继续通过。

手工回归时分别以“未配置设备”“已配置但设备不可达”“设备在线”三种状态打开页面，确认顶部状态真实、主体布局一致，并确认在线操作未受影响。

# 节拍器状态与音频页面窄屏修复设计

## 问题

设备在节拍器停止时仍返回默认 BPM 90，小程序的每秒状态轮询无条件采用该值，导致用户刚选择的 BPM 被覆盖。音乐页面的原生按钮没有明确网格宽度，在手机窄屏下会撑开搜索栏、分页栏和文件行。节拍器预设与校准音使用多行大按钮，页面过长。

## 初版设计复盘

初版尝试将 6 个 BPM 和 5 个校准音原生 `<button>` 强制放进单行 Grid。微信真机的原生按钮仍保留最小内容宽度，Grid 因此超出视口，造成整个页面横向滚动、左侧内容被裁切。WXML 中的 `&amp;` 在当前真机环境也被按普通文字显示。该方案停止使用。

## 最终设计

- 只有设备节拍器处于运行或暂停状态时，小程序才同步设备 BPM、拍号和拍序；停止状态保留页面当前选择。
- 音乐搜索、清空、刷新、文件播放、翻页和底部停止等小型操作改用普通 `<view>` 点击控件，避免原生按钮最小宽度干扰布局；需要禁用的控件通过样式类和现有处理函数共同限制。
- 分页栏固定为三列，中间页码不换行。
- 六个常用 BPM 改用普通 `<view>` 点击卡片并保持一行；手动 BPM、拍号和播放控制各保留一行。
- 五个校准音改用普通 `<view>` 点击卡片并保持一行，保留音名和频率。
- 音频页面和音乐页面禁止横向溢出；所有紧凑控件使用百分比分栏和 `min-width: 0`，不依赖原生按钮固有宽度。
- 英文标题直接使用 `RHYTHM · PITCH`，不使用 HTML 实体。
- 保持现有颜色、接口和操作逻辑，不修改 P4/C5 固件协议。

## 验证

- 停止状态选择 60、120 或手动 BPM 后等待多个轮询周期，页面值不回到 90。
- 开始或暂停节拍器后，页面仍能同步设备实际 BPM 和拍号。
- 720 像素截图对应的窄屏下，页面不能左右滚动，搜索、清空、页码和翻页控件均不溢出或换行。
- 标题显示 `RHYTHM · PITCH`，不能显示 `&amp;`。
- JavaScript 与 JSON 静态检查通过；本轮仅涉及小程序，无需重新编译 P4 固件。

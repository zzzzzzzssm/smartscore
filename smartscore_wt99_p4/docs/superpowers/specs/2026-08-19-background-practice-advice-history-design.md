# 练习建议后台生成、设备查看与小程序历史设计

## 目标

练习建议不再由小程序按钮同步触发。每次本地评分完成后，设备在联网时自动启动一次 DeepSeek 建议任务，使云端等待与用户查看评分并行进行。

设备评分页可以查看当前这次练习的建议。设备不保留建议历史；开始下一次练习或设备重启后，上一条设备建议失效。小程序继续沿用现有同步边界，只为通过小程序结束并写入 `practiceRecords` 的练习保存建议，用户可以从历史记录反复查看。

只有练习结束并完成本地评分时设备已经联网，才允许启动建议任务。结束时离线则本次直接跳过，之后恢复网络也不补跑。

## 范围边界

本次修改包括：

- 设备端自动建议任务、单任务状态机和当前练习内存缓存；
- 设备评分页的建议入口、状态提示和可滚动建议页；
- 设备 HTTP 状态与建议读取接口；
- 小程序自动同步、练习记录建议回看和用户页清理缓存；
- 对应的设备端、小程序端自动化测试和硬件验收步骤。

本次不包括：

- 设备历史建议列表或建议持久化；
- 云端账号、跨手机同步或设备独立练习的历史补同步；
- 结束时离线后的自动或手动补跑；
- 旧练习建议补生成；
- 评分公式、DeepSeek 提示词和响应结构、乐谱识别、语音功能的修改。

## 方案选择

采用设备评分事件驱动方案。另两个被排除的方案是：

1. 由 HTTP 接口创建异步任务：改动较少，但设备屏幕或语音结束练习时不会自动生成。
2. 由小程序后台生成：依赖手机页面存活，无法支持设备独立查看，且微信后台执行不可靠。

设备评分事件是所有结束路径的共同汇合点。把触发点放在这里，可以保证设备、小程序和语音结束流程行为一致，也能避免多个入口重复创建云端请求。

## 组件与职责

### `practice_advice_service`

新增独立 ESP-IDF 组件，负责：

- 为新练习创建仅在本次启动周期内唯一的 `session_id`；
- 维护建议状态、错误码、用户可读消息和当前建议 JSON；
- 在评分完成时检查网络并决定启动或跳过；
- 复制本次评分 JSON，在独立低优先级 FreeRTOS 任务中调用现有 `deepseek_advice`；
- 保证同一 `session_id` 最多调用模型一次；
- 丢弃已经被新练习失效的旧任务结果；
- 为设备界面和 HTTP API 提供线程安全的状态快照与结果读取接口。

组件只依赖网络状态和 `deepseek_advice`，不负责屏幕、小程序格式或评分计算。

### `scoring_service`

`scoring_service_start()` 成功时开始一个新的建议会话，同时清除设备上的上一条建议状态。评分任务成功提交本地评分 JSON 后，把相同 `session_id` 和结果交给 `practice_advice_service`。

建议任务永远在本地评分结果已经安全提交后才启动。建议失败不会改变评分服务的 `READY` 状态，也不会覆盖或删除本地评分结果。

### `screen_adapter`

`screen_adapter` 在现有评分结果页上动态创建“练习建议”按钮，并根据建议服务快照处理点击。建议内容以独立的全屏、可滚动 LVGL 页面呈现，使用现有 SD 卡中文字库和应用字体回退链。建议页提供返回评分页按钮。

按钮和建议页均为运行时对象，不修改 UI Guider 自动生成文件。

### `device_api`

`device_api` 只读取建议服务状态，不创建第二个模型任务。它把 `session_id` 带入评分和状态响应，供小程序建立可靠关联。

### 小程序

小程序负责把设备当前建议同步到对应 `practiceRecords` 项、展示状态和历史内容。小程序不再拥有“生成建议”的职责。

## 会话和状态机

建议状态固定为：

- `none`：当前没有练习或建议状态；
- `waiting_score`：新练习已经开始，等待本地评分完成；
- `running`：评分完成时已经联网，作业正在等待唯一工作任务或正在请求 DeepSeek；
- `ready`：经过现有 schema 校验的建议已缓存；
- `skipped_offline`：评分完成时设备未处于 `NETWORK_STATE_WIFI_CONNECTED`；
- `failed`：已联网并进入生成流程，但因配置、内存、传输、超时、HTTP 或响应校验失败而终止。

状态转换如下：

```text
开始练习
  -> waiting_score
  -> 本地评分失败：failed（仅说明建议无可用评分输入）
  -> 本地评分成功 + 结束时离线：skipped_offline
  -> 本地评分成功 + 已联网：running
       -> DeepSeek 成功且 schema 有效：ready
       -> 请求或校验失败：failed
```

`skipped_offline` 和 `failed` 都是本次练习的终态，不自动重试。设备获得 Wi-Fi IP 只代表允许尝试外网请求；若实际互联网不可达，DeepSeek 请求返回网络失败并进入 `failed`。

每个工作任务持有自己的评分 JSON 副本和会话令牌。开始下一次练习时，服务立即增加令牌并清空对外可见的旧结果；无法立即取消的旧 HTTPS 请求可以自然结束，但提交结果前必须再次比较令牌。令牌不匹配时释放旧结果，不改变新会话状态。服务使用一个常驻工作任务和一个“仅保留最新会话”的待处理槽，保证物理上也不会同时运行两个 DeepSeek HTTPS 请求；新会话在旧请求收尾后处理，设备对外仍统一显示 `running`。

设备当前建议只保存在内存中。它不写入 NVS 或 SD 卡，重启后回到 `none`。

## 后台任务与资源约束

- 同一时间最多存在一个 DeepSeek HTTPS 请求和一个最新会话待处理作业；更旧的待处理作业会被新会话替换并释放。
- DeepSeek 调用继续使用现有超时、最大响应大小和严格 schema 校验。
- 大的评分输入副本和建议 JSON 优先使用 PSRAM；分配失败进入 `failed`，不影响评分。
- 后台任务优先级低于评分和关键输入任务，不持有 LVGL 锁，不从工作任务直接操作界面。
- 建议状态通过互斥锁保护；界面和 HTTP 读取使用短时快照，不等待 HTTPS 请求完成。
- 现有 socket 预算继续生效。小程序通过状态轮询读取，不再用一个长时间占用 HTTP 请求同步生成建议。

## HTTP 协议

### `/api/status`

在现有响应中增加：

```json
{
  "practice_session_id": "boot-<id>-practice-<counter>",
  "advice_state": "running",
  "advice_ready": false
}
```

这些字段是摘要，不包含完整建议，避免扩大每秒轮询负载。

### `GET /api/practice/advice`

所有建议业务状态使用可解析的 JSON 返回。基本形状为：

```json
{
  "ok": true,
  "session_id": "boot-<id>-practice-<counter>",
  "state": "ready",
  "ready": true,
  "message": "练习建议已生成",
  "advice": {}
}
```

只有 `ready` 响应包含 `advice`。`skipped_offline` 和 `failed` 包含稳定的 `error_code` 与中文 `message`。`running` 返回可轮询状态，不阻塞等待。

### `POST /api/ai/score`

保留旧路由以避免旧客户端收到 404，但它不再创建任务：

- `ready`：HTTP 200，并按旧协议直接返回当前建议对象；
- `running` 或 `waiting_score`：HTTP 202，返回与新 GET 接口相同的状态对象；
- `skipped_offline`：HTTP 409，返回稳定错误码 `advice_skipped_offline`；
- `failed`：HTTP 502；仅密钥未配置使用 HTTP 503，并返回原 DeepSeek 错误码；
- `none`：HTTP 409，返回 `advice_not_available`。

任何调用次数都不会重复请求 DeepSeek。

### `/api/stop` 与 `/api/result`

评分结果增加 `practice_session_id`，值与建议服务一致。现有评分字段保持原形，不增加额外包装层，避免破坏小程序的评分解析。

## 设备界面

评分结果页增加一个始终可点击的“练习建议”按钮。点击行为为：

- `ready`：打开完整建议页；
- `running` 或 `waiting_score`：提示“建议正在后台生成，请稍等”；
- `skipped_offline`：提示“本次练习结束时设备未联网，未生成建议”；
- `failed`：根据稳定错误码显示网络中断、请求超时、密钥未配置、内存不足或模型响应异常；
- `none`：提示“请先完成一次练习”。

按钮不因 `running` 而禁用，这样用户点击时可以得到明确的等待提示。建议完成后，按钮文字可以更新为“查看练习建议”。

建议页按现有结构依次展示：

1. 总结；
2. 一至三项重点问题、证据、练习动作、BPM、分钟数、重复次数和达标目标；
3. 下次练习总时长和分步计划；
4. 鼓励语和数据不足说明。

页面允许纵向滚动，不截断长建议，也不展示或计算新的 AI 分数。

## 小程序行为

### 练习页

原“AI 练习建议”按钮改为只读状态/查看入口：

- `waiting_score` 或 `running`：显示“建议生成中”；
- `ready`：显示“查看练习建议”；
- `skipped_offline` 或 `failed`：显示“建议未生成”，点击可查看原因；
- `none`：提示先完成练习。

小程序调用 `/api/stop` 得到评分和 `practice_session_id` 后，立即创建练习记录。新增字段固定为 `practiceSessionId`、`adviceStatus`、`advice`、`adviceText` 和 `adviceMessage`；初始 `adviceStatus` 为 `pending`。随后在页面可见期间利用现有状态轮询观察 `advice_state`。看到 `ready` 后只调用一次完整建议接口，并把结构化建议及供展示使用的格式化文本写回具有相同 `practiceSessionId` 的记录。

页面隐藏或卸载后停止轮询。再次进入练习页时，若设备当前 `session_id` 与某条待完成记录匹配，则继续同步。若设备已经进入下一次练习，旧记录转为小程序本地终态 `sync_missed`，显示“建议未完成同步”，且绝不把新建议写入旧记录。

终态必须写入记录：

- 成功：`ready`；
- 结束时离线：`skipped_offline`；
- 生成失败：`failed`；
- 页面离开后设备会话已被下一次练习替换：`sync_missed`。

记录写入失败时保留已有数据，不静默删除旧记录，并提示“小程序本地存储空间不足”。

### 历史记录页

每条记录显示“建议生成中”“有练习建议”或“未生成”标记。详情面板在评分明细之外增加练习建议区域；有建议时可反复查看完整内容，未生成时显示保存的原因。

重命名保留建议字段。删除记录同时删除该记录内的建议。设备独立完成且小程序未参与的练习不进入小程序历史。

### 用户页清理缓存

新增“清理缓存”菜单项。点击后弹出二次确认，明确说明会清除设备地址、蓝牙设备和连接状态，但保留乐谱与练习历史。

确认后仅删除连接类键值，包括：

- `apiBaseUrl`；
- `bluetoothDevice`；
- `deviceState`。

不得调用 `wx.clearStorage()`。必须保留：

- `scores` 和乐谱文件；
- `currentScoreId`、`currentExternalScore` 与当前选谱；
- `practiceRecords` 及其中的建议；
- 乐谱迁移标记。

清理完成后同步清空应用内存中的连接地址，刷新页面，并提示用户需要重新连接设备。

## 错误处理

- API 密钥缺失在联网检查之后被识别为 `failed/deepseek_key_missing`，不会尝试 HTTPS。
- 评分结果不可用时不调用 DeepSeek，并记录稳定错误原因。
- 传输、超时、HTTP、响应过大、JSON 和 schema 错误沿用 `deepseek_advice_error_name()`，设备界面和小程序映射为简洁中文提示。
- 小程序重复轮询、重复点击或旧 `POST /api/ai/score` 调用都只能读取状态。
- 建议任务失败不影响评分查看、重新练习、返回选曲或其他设备功能。
- 建议页创建失败时保留缓存并显示界面内存不足提示，用户仍可通过小程序读取建议。

## 验证

### 设备自动化测试

- 新练习创建新 `session_id` 并清除上一条设备建议；
- 在线评分完成只创建一个任务；
- 结束时离线进入 `skipped_offline`，网络恢复后仍不创建任务；
- `running`、`ready` 和各类 `failed` 状态正确；
- 多次读取接口和旧 POST 路由不产生重复任务；
- 新练习使旧任务失效，旧结果不会覆盖新状态；
- 内存分配失败和无效建议 JSON 不影响本地评分结果；
- API 状态摘要和完整建议响应符合协议。

### 小程序自动化测试

- 结束练习后先保存评分，再自动同步建议；
- 只把建议写入 `practiceSessionId` 匹配的记录；
- 页面隐藏停止轮询，再次进入可恢复匹配会话同步；
- `running` 点击显示等待提示，离线和失败显示正确原因；
- 历史记录可以重复打开建议，重命名保留建议，删除一并移除；
- 清理缓存删除连接键并保留 `scores`、当前选谱和 `practiceRecords`；
- 现有小程序测试、语法检查和建议格式测试继续通过。

### 构建和硬件验收

在 ESP-IDF 工具链可用时构建完整固件。硬件至少验证：

1. 联网结束练习后，评分页立即可用且建议在后台生成；
2. 生成中点击设备按钮出现等待提示；
3. 完成后设备可滚动查看完整建议；
4. 小程序保存建议并能从历史记录重复打开；
5. 结束时离线不调用模型，设备和小程序均显示离线说明；
6. 结束后再恢复网络不会补跑；
7. 开始下一次练习后设备不再显示上一条建议；
8. 清理缓存后需要重新连接设备，但乐谱、当前选谱、评分记录和建议仍存在。

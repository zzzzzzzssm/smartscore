# Creator 标准记谱与防碰撞排版设计

## 目标

在不改变用户原始 MIDI 演奏内容、不引入云端 AI 的前提下，改善 Creator 五线谱的记谱正确性和可读性：

- 保守推断并稳定显示调号，减少可以由调号承担的重复升降号。
- 按标准小节作用域省略重复临时记号，并在需要时显示升、降、还原号。
- 正确排布密集和弦、二度音程、多声部音头和多列临时记号。
- 用符号真实边界约束横向间距；密集小节可以自动独占一行。
- 保存、重新打开、点击选音、着色和播放始终与原 MIDI 对应。

本设计遵循“清晰优先”的制谱原则。调号表示调性而不是视觉缩写；不能把单个密集和弦中的临时记号任意移到小节前。参考：

- [Music Publishers Association: Standard Music Notation Practice](https://www.mpa.org/wp-content/uploads/2018/06/standard-practice-engraving.pdf)
- [MusicXML 4.0 key signature](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/key/)
- [LilyPond automatic accidentals](https://lilypond.org/doc/v2.25/Documentation/notation/automatic-accidentals.html)
- [Dorico accidental stacking](https://www.steinberg.help/r/dorico-pro/6.1/en/dorico/topics/notation_reference/notation_reference_accidentals/notation_reference_accidentals_stacking_c.html)
- [SMuFL engraving defaults](https://w3c.github.io/smufl/latest/specification/engravingdefaults.html)

## 已确认的产品选择

1. 采用保守自动定调。只有证据充分且能显著减少临时记号时才采用调号；不确定时维持 C 调/开放调写法。
2. 采用可读性优先的动态系统宽度。密集小节可以一小节一行，普通内容仍尽量两小节一行。
3. 原始 MIDI 的 pitch、start tick、duration、note count 和播放数据不因记谱优化而改变。
4. 只使用本地确定性算法，不恢复此前删除的 Creator 云端 AI 整理。

## 当前问题

- `creator_recorder_snapshot()` 固定写入 C 大调，所有黑键在 Creator 中倾向显示成升号。
- MIDI 到书写音高的转换逐音执行，没有小节内临时记号状态；同一小节相同升音会重复显示升号。
- 小节理想宽度只统计起音列和时值，未计入和弦宽度、临时记号列、附点与不同声部的真实外框。
- 音符横坐标按 onset 比例直接插值，局部和弦避让结果没有反馈给相邻节奏列和系统换行。
- 保存格式固定写 `C major`，调号显示与重新打开后的结果可能不一致。

## 架构

保留现有数据链：

`creator recorder -> midi_data_t -> music_score_t -> music_layout -> scene -> LVGL`

在 `midi_data_t` 与 `music_score_t` 之间增加独立的确定性记谱规范化模块。该模块放在现有 `musicxml_renderer` 组件中，但不依赖 LVGL 或 Creator UI，供 Creator 和以后需要的 MIDI 书写视图复用。

模块职责分离如下：

- Creator recorder：只负责录制、量化和保存原始演奏事件。
- Creator notation session：保存本次创作的调号推断状态和锁定结果。
- MIDI notation normalizer：完成调号候选评分、增强音拼写、临时记号状态、和弦/声部语义和源音符映射。
- Music layout：只处理字形几何、节奏列间距、系统换行和场景输出。
- Music display/Leland view：负责调用、缓存、翻页、点击与着色，不再自行决定音高拼写。

## 实时与暂停行为

- 录制中立即执行小节临时记号状态和防碰撞排版，但不改变全局调号，避免每个 Note On 引起整谱跳动。
- 暂停时才进行调号推断。至少需要两个已完成小节和八个独立起音组；样本不足时保持未锁定，并在下一次暂停重新评估。
- 一旦候选达到接受条件，调号在本次创作剩余时间内锁定；继续录制不会再次换调。
- 外部 MIDI 已有显式调号，或调用方标记 `tonality_forced` 时，绝不重新推断。

## 保守调号推断

候选为五度圈 `-7..+7` 的调号；大小调共享相同调号时，调号选择先按记号成本决定，major/minor 元数据再按强拍、长音和结尾的主音支持度决定。

每个候选使用整数代价函数，包含：

- 按该调号拼写后仍需打印的临时记号数量和时值权重。
- 非调内长音、强拍音的额外惩罚。
- `abs(fifths)` 的复杂度惩罚，避免为少量色彩音选择六、七个升降号。
- 不自然的增强音程、连续同音异名和双升/双降惩罚；首版禁止自动生成双升、双降。

接受候选必须同时满足：

- 相比 C 调至少减少三个临时记号。
- 相比 C 调至少减少 35% 的临时记号成本。
- 最佳候选相对次佳候选至少有 15% 的成本优势。

任一条件不满足即保持 C 调/开放调。算法排序必须包含完整稳定的 tie-break，保证相同输入得到逐字段一致的输出。

## 音高拼写与临时记号

1. 先依据已锁定或显式调号确定主要升号/降号方向。
2. 色彩音在不使用双升、双降的候选拼写中选择代价最低者；代价考虑相邻旋律字母连续性、和弦三度结构和同音拼写一致性。
3. 临时记号状态按 `staff + diatonic step + octave` 保存，并在每个小节开始时从调号状态重新初始化。
4. 同一 onset 的和弦必须作为一个集合计算记号，再一次性更新状态，不能因事件输入顺序产生不同结果。
5. 同一小节、同一谱表、同音名和同八度的重复变音不重复显示记号。
6. 从变音恢复自然音，或从临时还原恢复调号音时，显示必要的还原、升或降号。
7. 跨小节延音线的 continuation 不重复显示临时记号。
8. 其他声部或另一谱表只用于判断是否需要提示记号，不得导致必要记号被隐藏。首批不增加括号提示字形；不确定时宁可保留普通提示记号。

## 和弦与多声部几何

- 只把量化后 onset 完全相同、staff 和 voice 相同的音组成同一和弦；不把快速琶音强行合并。
- 单声部同一和弦中的完全重复音高只画一个音头，但源映射保留全部原音符索引。
- 同一符干上的二度音程按符干方向交替错开音头；连续二度选择使错位音头数量最少的稳定排列。
- 单声部和弦共享一根包围最高、最低音头的符干。
- 多声部保持上声部符干向上、下声部符干向下。首批不合并跨声部音头，而是以完整和弦为单位错开，避免破坏点击和着色映射。
- 附点避开谱线并在同一节奏列内消除垂直冲突。

## 临时记号分列

每个 `onset + staff` 收集所有可见临时记号，包括不同声部，然后统一排布：

1. 从靠近音头的最右列开始放置。
2. 使用 SMuFL 字形边界判断垂直相交；边界不相交的记号可以共列。
3. 发生相交时向左建立新列；相邻二度记号必须分列。
4. 排序采用最高、最低交替向内的稳定顺序，使外侧记号尽可能共列并减少总列数。
5. 字形与音头的最小净距为 `0.35sp`，记号列间最小净距为 `0.15sp`，同列字形垂直净距为 `0.20sp`。
6. 优先使用当前字体的紧凑 glyph bbox；有 cut-out 数据时允许字形交错，但不得发生实际墨迹重叠。

## 节奏列约束布局

小节内先按 onset 建立 rhythmic columns，而不是直接逐事件计算 x。

每列先完成和弦音头、符干、临时记号和附点布局，再计算：

- `left_extent`：最左临时记号或左移音头。
- `right_extent`：最右音头、附点或符尾。
- `top/bottom_extent`：加线、符干、横梁和已有连接的垂直范围。

相邻列满足：

`x[i+1] >= x[i] + right_extent[i] - left_extent[i+1] + 0.45sp`

在满足硬碰撞约束后，剩余空间按时值弹性分配，使节拍位置仍然容易辨认。不能通过把同一 onset 的音符整体拆成不同节拍位置来解决内部碰撞。

系统断行先计算每个小节的硬最小宽度和理想宽度：

- 普通内容优先两小节一行。
- 两个小节的硬最小宽度超出可用宽度时，密集小节独占一行。
- 单个小节仍过宽时，先移除非必要提示记号，再压缩弹性间距到硬下限；绝不缩小标准音符字形或允许墨迹相交。
- 若达到硬下限仍无法容纳，保留上一份稳定场景并返回明确的布局过密错误，不发布半成品场景。

谱表与系统间距使用上下 skyline 计算。加线、长符干、横梁、连音线或发音记号侵入相邻区域时，自动增大间距。

## 保存与兼容

- Creator 保存 JSON 新增 `key_explicit`；仅在调号已锁定时写数值字段 `key_fifths` 和布尔字段 `key_minor`。未锁定作品写兼容字符串 `key: "open"`，避免把开放调号误标成 C 大调；锁定时继续写规范旧 `key` 字符串以保持兼容。
- 读取时优先使用数值字段；旧文件继续解析 `C/G/D/...`、降号调和 minor 后缀。
- `midi_data_t` 中的调号值必须与保存值、预览值一致。
- 规范化输出维护 `notation event -> one or more source MIDI note indices` 映射；点击、着色和播放只通过该映射访问原音符。

## 内存与失败处理

- 更新时在 PSRAM 中构建一份有界的暂存 `music_score_t`/`music_scene_t`，全部成功后原子换入；不复制第二份原始 MIDI。暂存分配失败时继续显示上一份稳定场景。
- 排版工作区按 `MUSIC_MAX_EVENTS`/`MUSIC_MAX_MEASURES` 固定上限在堆上分配，大块内存由设备配置优先放入 PSRAM；不使用递归或无界容器。
- 调号推断最多 `15 × note_count` 量级；和弦临时记号排布最多对单个 onset 做有界平方复杂度。
- 任一分配、容量或几何校验失败时，保留上一份成功场景；录音、暂停、保存和返回主页仍可用。
- 错误日志区分内存不足、事件容量、场景容量、布局过密和非法输入。

## 验证与验收

实现时补充测试代码，但遵照本次用户要求不执行编译或测试，只进行静态引用和补丁检查。

必须覆盖的用例：

- G/Em 调中 F# 由调号承担，不在每个 F# 前重复显示升号。
- C 调同小节连续 C# 只在第一次显示升号；下一小节重新需要升号。
- G 调中的 F natural 显示还原号，同小节恢复 F# 时再次显示升号。
- Bb 调优先拼写 Bb 而不是 A#。
- 半音化、短片段或候选接近时不自动采用复杂调号。
- 同声部连续二度和 10 音密集和弦的音头、符干与记号边界不相交。
- 同一 onset 的不同声部临时记号共同分列。
- 普通小节保持两小节一行，密集小节自动一小节一行。
- 任意规范化前后原 MIDI pitch、start tick、duration 和 note count 完全一致。
- 保存、重开后的调号和临时记号数量一致。
- 随机容量边界输入不会产生非有限坐标、越界索引或半成品场景。

## 非目标

本轮不实现三连音识别、完整休止符补写、踏板时值语义重构、频繁局部转调、规范化层内部自动拆分跨小节长音，或完整替换为 MuseScore/LilyPond/Verovio。Creator recorder 已在快照阶段拆分跨小节长音并写入 tie；公共规范化接口对尚未拆分的输入返回明确错误，避免生成非法小节。这些属于后续独立设计，避免扩大本轮排版修复的风险。

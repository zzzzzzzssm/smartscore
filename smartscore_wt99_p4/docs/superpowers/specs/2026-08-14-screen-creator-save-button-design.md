# 屏幕创作者模式保存按钮设计

## 问题

屏幕端已经具备将创作结果保存到设备 SD 卡的能力，但保存入口位于暂停后才显示的“重弹覆盖”面板中，且按钮文案为“结束”。用户在录制界面看不到明确的保存操作，也无法从文案判断结束会同时保存。

## 设计

- 保持 `vendor/smartmusic_screen` 的哈希校验快照不变，在当前工程 `ui_app` 集成层适配其私有创作者控件。
- 复用创作者原有的 50 ms 自动暂停 UI 定时器同步按钮状态，不增加新的周期定时器。
- 将原“结束”按钮从重弹覆盖面板提升到创作者谱面顶部控制栏，改为常驻的“保存乐谱”主按钮，与“暂停/继续”和“退出”并列。
- 录制中点击“保存乐谱”时，先结束当前音符计时并暂停录制，再复用现有保存流程。
- 已暂停时点击“保存乐谱”，直接复用现有保存流程。
- “重弹覆盖”面板只保留区间选择提示，不再承担保存入口，避免保存操作随面板一起隐藏。
- 保存成功后沿用现有行为：停止创作并返回进入创作者模式前的页面。
- 没有可保存音符或 SD 卡写入失败时保留在创作页面，显示现有错误信息，允许继续录制或重试保存。
- 小程序 API 和远程“结束并保存”流程保持不变，避免扩大改动范围。

## 方案取舍

仅把原“结束”改为“保存”改动最小，但录制时入口仍不可见。新增确认弹窗能降低误触风险，却会打断演奏操作。常驻按钮配合录制中自动暂停，既让功能始终可发现，也保持一次点击完成保存，因此采用该方案。

## 静态验证

- 确认按钮不再是重弹覆盖面板的子对象，录制状态隐藏面板时仍可见。
- 确认录制和暂停两种状态都能进入保存逻辑。
- 确认退出时隐藏保存按钮，再次进入创作时恢复显示。
- 确认无音符与写卡失败仍停留在创作页面并保留错误提示。
- 按要求不执行固件编译。

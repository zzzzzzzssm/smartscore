# 实时跟谱节奏容错设计

## 目标

放宽实时跟谱的起音时间容错。演奏者相对目标起音提前或延后不超过
300ms 时，跟谱仍匹配当前音符且不显示节奏错误；超过该范围时继续按现有逻辑
提示明显的节奏偏差。

## 修改范围

只调整 `components/screen_adapter/src/screen_adapter.c` 中实时跟谱候选音符的
时间窗口，使提前和延后方向都使用现有的 `SCREEN_RHYTHM_TOLERANCE_MS`。
候选匹配后仍由同一容差计算 `onset_ok`，避免“可以匹配”和“判定正确”使用
不同阈值。

本次不修改音高容差、音符时值判定、速度估计、演奏结束后的评分引擎、
输入事件时间戳或页面显示逻辑。

## 数据流与边界

实时 Note On 事件进入候选窗口搜索。时间差绝对值不超过 300ms 的候选可以
参与现有的音高和顺序匹配；匹配成功后按相同的 300ms 阈值设置起音结果。
超过窗口的事件仍不能匹配当前目标音符，并保留现有多余音或节奏错误行为。

## 验证

- 检查候选窗口与起音正确性判定引用同一个 300ms 常量。
- 验证提前或延后 300ms 内可以匹配且 `onset_ok` 为真。
- 验证明显超过 300ms 的事件不会被当作节奏正确。
- 运行相关测试或至少完成对应组件的编译检查。

# ESP-SR 中文命令同义词扩展设计

## 目标

在不改变现有唤醒、识别状态机和纯数字输出协议的前提下，将七个动作从每个动作一条固定口令扩展为每个动作十五条自然中文说法，共 105 条识别短语。

所有别名必须继续严格映射到原有命令 ID：

- 开始练习：1
- 停止练习：2
- 下一页：3
- 上一页：4
- 重新开始：5
- 查看评分：6
- 返回首页：7

## ESP-SR 接口依据

项目当前使用 `espressif/esp-sr` 2.4.6。组件实现确认 `esp_mn_commands_add(command_id, string)` 使用短语字符串去重，因此不同短语可以重复使用同一个 `command_id`。

ESP32-S3 接口限制为最多 400 条短语，单条短语长度为 2 至 63。设计总量为 105 条，低于组件上限。

所有短语逐条调用 `esp_mn_commands_add()` 注册，全部注册完成后只调用一次 `esp_mn_commands_update()`。每次命令识别结束后继续调用 MultiNet 的 `clean()` 重置解码状态；该操作不会清除命令表。

## 拼音生成

`mn7_cn` 注册内容使用空格分隔的拼音。105 条中文短语必须批量交给 ESP-SR 组件自带的 `tool/multinet_pinyin.py` 生成，不能手写或人工猜测拼音。

生成后需要检查：

- 105 条中文短语都有对应的非空拼音。
- 不同命令 ID 之间不存在完全相同的拼音字符串。
- 每条拼音字符串均满足 MultiNet 长度限制。
- “重新开始”和“重头开始”中的多音字由官方工具决定读音。

## 代码结构

`voice_recognition.c` 保留两个逻辑概念：

1. 七条规范命令：保存 ID 和串口调试日志使用的规范中文名称。
2. 105 条识别别名：每条保存目标 ID、中文短语和官方工具生成的拼音。

命令注册遍历识别别名表。识别结果仍只使用 `command_id` 查找规范中文名称，因此同义词不会改变数字协议，也不会依赖 MultiNet 返回具体别名。

编译期检查应确保规范命令表恰好包含七项。运行时注册必须检查每次 `esp_mn_commands_add()` 的返回值，并在失败日志中打印对应 ID 和中文短语。

## 状态与输出

状态流程保持不变：

1. 等待“你好小智”。
2. 唤醒后只进入一次命令识别。
3. 任一别名识别成功后输出对应的 1 至 7。
4. 输出数字后立刻结束本轮、清理 MultiNet 状态并返回等待唤醒。

纯数字输出格式保持：

```c
printf("%d\n", command_id);
fflush(stdout);
```

仅唤醒、超时、噪声、无效 ID 和未识别短语都不能输出数字。

## 冲突控制

词表不加入“返回上一页”，因为它与 ID 7 的“返回首页”具有高度相似的声学结构。也不加入“开始吧”“停止”“上页”“下页”等过短口令，以降低环境语音触发概率。

“上一页”和“下一页”本身是不可避免的近似命令，需要作为硬件测试重点。方向扩展词优先使用“往前/往后”“向前/向后”和“前一页/后面一页”增强差异。

## 文档与验证

README 更新为七个 ID 对应多种说法，并说明全部别名共享相同数字输出。

软件验证包括：

- 官方拼音工具成功处理 105 条短语。
- 检查短语数量、ID 范围、拼音非空和跨 ID 拼音重复。
- ESP-IDF 完整构建成功。
- 启动日志中 105 条短语均被 MultiNet 接受。

硬件验收包括：

- 每个 ID 至少抽测五条不同说法。
- ID 3 与 ID 4 的十五条说法逐条重点测试。
- ID 4 与 ID 7 做交叉误识别测试。
- 每次唤醒最多输出一个纯数字。
- 不唤醒直接说任意别名不能输出数字。
- 只唤醒后等待超时不能输出数字。

软件构建成功不能替代实际开发板上的识别率和误识别测试，不宣称尚未执行的硬件测试结果。

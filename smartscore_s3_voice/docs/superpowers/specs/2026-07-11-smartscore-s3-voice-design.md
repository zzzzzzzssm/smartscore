# SmartScore S3 离线语音识别设计

## 目标和边界

工程仅为 ESP32-S3-N16R8 和单个 INMP441 实现本地离线中文唤醒与命令识别。语音链路使用 ESP-IDF 标准 I2S RX 接口和乐鑫官方 `espressif/esp-sr` 2.4.6 组件，不包含网络、蓝牙、显示、音频输出或板间通信。

目标工具链为本机 ESP-IDF v5.1.2。ESP-SR 在 `main/idf_component.yml` 中固定为 2.4.6，避免组件 API 或模型集合在后续解析时发生未经验证的变化。

## 硬件和音频输入

I2S0 作为主机，仅创建标准模式 RX 通道。采样率为 16000 Hz；根据 `Netlist_PCB1_2026-07-21.tel` 中 U4 的连接，BCLK/WS/DIN 分别使用 GPIO10/GPIO11/GPIO9，不使用 MCLK。INMP441 的 L/R 接地，因此读取左声道；DMA 原始样本使用 32 位容器。

`audio_inmp441` 初始化和读取 I2S，将 INMP441 有效位对齐到 `int16_t`，在缩放后显式限制到 `INT16_MIN` 至 `INT16_MAX`。音频循环不动态分配内存。模块累计平方和，并约每秒打印一次 RMS。

## ESP-SR 数据流

组件下载后，以 2.4.6 的实际头文件、模型清单和官方中文命令识别示例为唯一 API 依据。模型通过 ESP-SR 模型分区加载，WakeNet 从实际模型列表中选择官方“你好小智”模型；MultiNet 选择当前组件提供的中文模型。实际开发板启动验证表明 `mn7_cn` 动态命令注册需要拼音，因此使用组件自带 `tool/multinet_pinyin.py` 生成全部七条命令的拼音；“重新开始”的结果为 `chong xin kai shi`，不手工推测多音字。

AFE 使用单麦克风输入，启用 VAD 和噪声抑制，关闭 AEC、BSS 和所有双麦克风算法。采集任务调用 AFE 官方接口取得 feed chunk size，识别任务调用官方接口取得 fetch chunk size，两者均不写死帧长度。

数据流为：INMP441 → I2S RX → 饱和 int16 PCM → AFE feed → AFE fetch → WakeNet 状态 → MultiNet。

## 状态机和命令映射

启动后处于 `WAIT_WAKE`。WakeNet 检测到“你好小智”后只打印“唤醒成功，请说出命令”，重置 MultiNet 并进入 `WAIT_COMMAND`。唤醒词本身不产生数字。

命令映射固定为：

1. 开始练习 → 1
2. 停止练习 → 2
3. 下一页 → 3
4. 上一页 → 4
5. 重新开始 → 5
6. 查看评分 → 6
7. 返回首页 → 7

MultiNet 返回合法 ID 1–7 后，先用普通日志报告识别结果，再单独执行 `printf("%d\n", command_id); fflush(stdout);`。随后立即停止本轮命令识别、重置 MultiNet 并回到 `WAIT_WAKE`，保证一次唤醒最多输出一个数字。超时、拒识、噪声或越界 ID 均不输出数字。

## 启动、错误处理和验证

`app_main` 检查目标芯片、Flash 容量和 PSRAM 初始化/容量，依次初始化麦克风及语音识别对象，再创建采集和识别任务。所有关键返回值均检查；初始化失败时输出具体阶段和错误，并停止继续创建依赖于该阶段的任务。

工程验证包括：组件管理器依赖解析、ESP32-S3 目标配置、完整编译，以及对最终配置、模型分区大小、模型名称、命令注册结果和栈/堆使用的静态检查。没有连接开发板时不宣称完成麦克风或识别准确率的硬件验证。

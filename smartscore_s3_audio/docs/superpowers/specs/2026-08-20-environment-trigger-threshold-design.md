# 环境触发门限与安静校准设计

## 背景与目标

实机日志出现过 `mic1_noise=0.89134`、`mic1_gate=2.22835`，而归一化音频峰值约为 `1.1`。这说明启动时的琴声或削顶帧被平均进环境底噪，导致后续琴音无法越过活动门限。

本次修改只降低“声音是否进入识别”的环境触发要求，并阻止强声污染启动校准。不得放宽音符、泛音、和弦或多音候选阈值，不修改 P4 通信，也不执行编译、烧录或实机测试。

## 方案

采用“适度降低门限 + 安静帧准入 + 有界超时”方案：

- 将 `MUSIC_NOISE_GATE_MULTIPLIER` 从 `2.5f` 调整为 `1.7f`。
- 每路麦克风独立判断校准帧。只有指标为有限值、未削顶、`RMS <= 0.05f` 且 `peak <= 0.20f` 的帧才计入环境底噪。
- 每路记录有效帧和拒绝帧数量。经过至少 1000 ms 且每路获得至少 20 个有效帧后完成校准。
- 校准最长等待 3000 ms。超时时，有有效帧的通道使用其有效帧均值；没有有效帧的通道使用 `0.002f` 的保守默认底噪，绝不使用被拒绝的强声均值。
- 最终活动门限仍不得低于现有 `MUSIC_MIN_RMS`，并限制为不高于 `0.020f`，防止异常底噪再次封锁弱单音。
- 运行期现有的环境底噪缓慢跟踪保留；削顶帧和已判断为乐音的帧仍不允许向上抬高底噪。

## 代码边界

- `main/music_detector_config.h`：定义新的门限倍数、校准准入、最少有效帧、超时、默认底噪和最大活动门限常量。
- `main/audio_preprocess.h/.c`：增加有效/拒绝帧计数，只累计合格安静帧，并统一通过有上下界的函数计算活动门限。
- `main/music_detector.c`：按“最短时间 + 有效帧数”结束校准，超时走安全回退，并输出校准状态与计数。

不修改 `chord_detector`、`piano_note_tracker`、YIN、音符分类器、UART 协议或 P4 项目。

## 日志与故障处理

完成时输出 `status=quiet` 或 `status=timeout`，以及两路麦克风各自的有效/拒绝帧数量、底噪和最终门限。某一路没有安静帧不会阻塞另一条健康通道，也不会让整个识别任务无限等待。

## 源码级验收条件

- 环境门限倍数为 `1.7f`，正常底噪下比当前 `2.5f` 更容易触发弱音。
- 琴声、削顶或明显强声不会写入启动底噪累计。
- 校准最多等待 3 秒，不会产生大于 `0.020f` 的活动门限。
- 单音、和弦和多音候选阈值完全不变。
- 校准日志可直接区分正常完成和超时回退。
- 按用户要求，不执行编译、烧录和实机测试。

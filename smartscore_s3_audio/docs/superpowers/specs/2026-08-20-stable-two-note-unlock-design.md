# 稳定双音放行设计

## 背景与目标

实机持续弹奏 `C4+F4` 时，传统分类器已经能够间歇输出
`INTERVAL [C4,F4]`，但精确琴键流通常只输出 `F4`。频谱日志表明
`F4` 是主音，较弱的 `C4` 在多帧中持续存在，但当前跟踪器只依据单帧
可信独立基频数量决定是否解除单音锁。`C4` 的单帧显著度或基频突出度
偶尔略低于硬门限，导致每帧 `independent_count` 仍为 1，并被单音锁清除。

本次只解决稳定两音演奏，首要验收样例是 `C4+F4`。现有单音去假八度
保护、61 键范围、最多四键输出以及 P4 UART 协议均保持不变。按用户要求
只修改源码，不执行编译、烧录或实机测试。

## 方案选择

采用“较弱第二音的时间累计 + 传统 INTERVAL 加速确认”方案：

- 不全局降低可信独立基频门限，否则单音泛音可能再次成为假和弦。
- 不把传统 `INTERVAL` 作为唯一来源，因为它在实机日志中并非每帧稳定
  输出，单独依赖它会使琴键集合断续。
- 保留当前帧的强独立基频判据；仅对一个具有自身基频支持的较弱第二音
  跨帧累计。连续稳定后，该第二音可解除单音锁并进入原有多音跟踪。
- 当传统分类器在同一帧接受的两音 `INTERVAL` 与主音、第二音一致时，
  增加确认进度，但不能跳过物理基频支持检查。

## 第二音候选与时间确认

`piano_note_tracker` 为 61 个琴键保留轻量的第二音确认计数，内存继续位于
现有 PSRAM DSP 上下文。仅当存在位于琴键范围内的 YIN 主音时启用这条
时间确认路径；没有 YIN 主音时完全沿用当前逻辑。每次更新从主音之外的
琴键中选择显著度最强的一个候选。候选必须同时满足：

- 不是当前 YIN 主音；
- `chord_detector` 报告自身物理基频，或者是已由低频 YIN 确认的虚拟低音；
- 琴键显著度至少 `0.18`（高于频谱最低支持值 `0.16`）；
- 基频突出度至少 `1.05`；
- 位于 MIDI 36..96；
- 当前帧信号有效。

弱第二音累计不接受与主音相差整数八度的候选。真实八度仍使用原有严格的
双独立基频放行，避免恢复此前的单音假八度。

候选每个合格帧增加一次确认计数；同一未削顶有效帧中的其他候选各减一次，
使不同音高不能共享累计结果。同一音对按无序集合累计，因此 YIN 主音在
`C4` 与 `F4` 之间交换时不会丢失此前进度。传统分类器输出恰好两个音的
`CHORD_DETECTION_INTERVAL`，并且两音集合与主音和候选一致时，本帧额外
增加一次。累计达到 3 次后，该候选成为“稳定第二独立音”。计数不是永久
积分：没有候选的未削顶有效帧会让所有计数各减一次，降到零后失效。

这些较宽松门限仅用于稳定第二音确认，不替换现有
`0.50` 显著度和 `1.20` 突出度的单帧可信独立基频门限。

## 单音锁与双音状态

当前帧存在至少两个强独立基频时，行为完全沿用现有多音路径。否则，如果
主音之外已有稳定第二音，则把它计入多音解锁条件，禁止单音锁清除该候选，
并只允许主音和该稳定第二音进入双音起音跟踪。稳定第二音的证据只在确认后
托底到现有 `0.45` 起音门限，随后仍需连续两帧起音；其余琴键的证据不被
提高。这样持续但较弱的 `C4` 能够真正激活，而单帧弱峰不能绕过起音规则。

在稳定第二音尚未确认前继续保持单音锁，因此单音产生的瞬时八度、五度和
低频伪峰不会立即显示。稳定第二音消失后，活动琴键仍按现有两帧释放规则
退出；确认计数归零后恢复正常单音保护。

若没有稳定第二音且当前帧只有一个强独立基频，精确琴键流仍保持单音。
本次不放宽第三、第四音；现有强独立基频达到两个时，多音路径仍可按原规则
处理更多琴键。

## 削顶、切麦和错误输入

选中麦克风削顶时继续禁止任何新按键起音，同时冻结第二音确认计数：既不
利用削顶频谱增加计数，也不因该帧清空此前的稳定证据。下一未削顶有效帧
再继续确认或衰减。这样短时削顶不会建立假和弦，也不会立刻破坏已积累的
`C4+F4` 证据。

麦克风健康状态变化不改变协议；候选只使用 `chord_detector` 已完成融合后
的每键证据。错误低频 `F2` 若没有连续自身基频支持或低频 YIN 对同一 MIDI
的确认，不能成为稳定第二音。

## 代码边界与数据流

1. `chord_detector` 继续输出每键显著度、基频支持、突出度及传统分类结果。
2. `piano_note_tracker` 在现有单帧强独立基频判断之前更新第二音计数。
3. 跟踪器合并“当前强独立音”和“稳定第二音”决定是否解除单音锁。
4. 最终 `piano_note_set_t` 仍由现有
   `music_uart_link_submit_note_set()` 发送，不改变任何 P4 字段。

预期修改范围仅为：

- `main/piano_note_tracker.h`
- `main/piano_note_tracker.c`

除非实现时发现现有 `chord_result_t` 信息不足，否则不修改
`chord_detector`、`music_detector`、P4 协议、采样率、增益或环境门限。

## 日志与验收

新增日志只在稳定第二音确认或失效时输出，包含主音、第二音、累计次数以及
是否得到 `INTERVAL` 加速，不得逐帧刷屏。

源码与后续实机验收条件：

- 持续弹奏 `C4+F4` 时，确认延迟后稳定输出
  `PIANO_KEYS [C4,F4]`，不再长期仅输出 `F4`。
- `INTERVAL [C4,F4]` 可加速确认，但单帧分类结果不能独自建立第二音。
- 单独弹奏 `F4`、`C4`、`A4` 时仍只输出一个琴键，不恢复假八度。
- 混合波形产生的 `F2` 不得与 `F4` 组成假双音。
- 削顶帧不增加或清零第二音确认计数，也不得建立新按键。
- 第二音停止后按现有释放规则退出，不长时间粘滞。
- P4 UART 协议、最大四键限制和 61 键 MIDI 范围不变。
- 本轮不执行编译、烧录或实机测试。

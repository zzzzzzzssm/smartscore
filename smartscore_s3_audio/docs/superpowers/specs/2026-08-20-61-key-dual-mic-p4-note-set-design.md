# 61 键双麦精确多音识别与 P4 可靠传输设计

## 目标

在现有 ESP32-S3、ES7210 和两块 IM68A130 硬件上，面向一台标准 61 键电子琴扬声器，实现 C2--C7（MIDI 36--96）的单音及最多四个同时琴键识别，并将具体 MIDI 琴键和八度可靠传给 ESP32-P4，用于跟谱和评分。

首版使用条件固定为：

- 电子琴未启用移调；
- 不使用延音踏板；
- 同时发声琴键数不超过 4；
- 结果必须包含具体 MIDI 和八度，不能只输出音级或和弦名称；
- 正常确认时间主要落在 180--300 ms；
- 识别核心不依赖固定和弦字典，任意 2--4 键组合均可输出；
- 诊断 PCM 采集默认关闭，正式运行不保存或传输原始音频。

实机目标为：61 个单音总体准确率不低于 95%，双音和三音精确集合准确率不低于 90%，四音精确集合准确率不低于 80%，静音、人声和敲击误触发率低于 2%。这些是目标板验收指标，必须用实际电子琴录音和双板日志验证，不能由编译成功代替。

## 非目标

- 不支持 88 键 A0--C8；
- 不支持移调后的键盘映射；
- 不支持延音踏板形成的历史音重叠；
- 不支持超过 4 个同时发声音符；
- 不承诺真实原声钢琴、多乐器或不同音色设备无需数据校准即可达到同一准确率；
- 不在实时音乐链路中传输连续 PCM；
- 不重写 P4 已有跟谱和评分系统，只为它提供可靠的逐键事件。

## 当前实现差距

当前 S3 固件已经具备双麦同步采集、每路校准、质量选择、YIN、4096 点 FFT、大/小三和弦分类以及 UART NDJSON 链路，但仍有以下限制：

1. 单音最低频率约为 C2，而和弦候选仅覆盖 MIDI 48--84，不能覆盖整台 61 键琴。
2. 复音结果主要按音级和大/小三和弦模板判断，具体八度不够可靠，也不能表达任意四键组合。
3. 严格模式只选一路进行一次 FFT；演示模式虽然能融合双麦，但仍不是面向逐键转录的特征融合。
4. P4 只把 `note_on` 和 `note_off` 送入跟谱与评分；`poly` 仅用于诊断。S3 当前会把复音压缩成一个旋律音，造成和弦琴键丢失。
5. 两端源码当前实际使用 115200 baud，但 P4 协议文档仍残留 460800 baud、旧 S3 GPIO 方向和旧 H7 针号。

## 总体数据流

```text
ES7210 双槽 PCM
  -> 每路预处理和噪声/削波统计
  -> 每路质量与分频段 SNR
  -> 单音 YIN + 每路 61 键谐波显著度
  -> 质量加权的特征级双麦融合
  -> 最多四键的稀疏候选分解
  -> 逐键时间跟踪和集合稳定
  -> MusicLink v2 完整琴键集合
  -> P4 集合差分
  -> 现有逐键 note_on/note_off 跟谱与评分入口
```

S3 始终是声学识别结果的来源。P4 不向 S3 下发期望乐谱来限制候选，避免把“按乐谱猜音”当成真实识别；P4 只负责会话、可靠传输、集合差分和业务消费。

## S3 采集与预处理

硬件格式保持不变：24 kHz、16 bit 有效数据、16 bit 槽、标准双槽 I2S、1024 帧采集块。MIC1 和 MIC2 从同一 I2S 帧同步拆分，分别维护预处理、噪声估计和历史状态。

当前两级 50 Hz 高通会明显削弱 C2 基频。新实现使用每路独立的二阶 25 Hz Butterworth 高通，保留 C2 的基频能量，同时去除直流和超低频机械扰动。滤波器状态在启动、增益切换、采集恢复和显式重新校准时清零。

每路保留以下统计：

- RMS、峰值、削波率、均值和峰均比；
- 总体噪声 RMS 与动态门限；
- 低、中、高三个频段的噪声底和 SNR；
- 连续有效、无效、削波和噪声帧数；
- 最近一次增益或通道状态变化时间。

启动校准期间不产生琴键结果。校准完成后，噪声底只在无音调、无削波且没有活动琴键时慢速上升；持续琴音期间冻结向上学习，避免把长音吸收到噪声底。

## 双麦质量和特征融合

每路状态为 `INVALID`、`WEAK`、`VALID`、`GOOD`、`CLIPPED` 或 `NOISY`。判断依据包括相对本路噪声底的 SNR、峰值、削波、直流偏移、峰均比和连续性。

- 一路无效而另一路有效时立即使用有效通道；
- 两路都无效时输出空琴键集合，不猜测音符；
- 削波或宽带冲击通道不参与谐波显著度融合；
- 两路都健康时分别计算频谱和 61 键显著度，不进行未对齐的波形相加；
- 每个频段使用该通道在本频段的质量权重；
- 两路有效时，某琴键的融合显著度为两路显著度的质量加权平均；只有一路有效时直接使用该路；
- 候选只在一路出现而另一路同频段也具有良好 SNR 时，需要通过更严格的局部峰和谐波一致性门限。

两路健康时每个分析周期执行两次 4096 点 FFT。若实测 DSP deadline 不满足，则自动降级为只分析总体质量更高的一路，并在状态和性能日志中报告 `single_mic_cpu_fallback`。降级不能阻塞采集，也不能改变 UART 数据结构。

## 单音和低音路径

单音使用两条互补 YIN 路径：

- C3--C7 使用现有 24 kHz、2048 点 YIN；
- C2--B2 将最近约 171 ms 的信号经抗混叠滤波后降采样到 6 kHz，再使用 1024 点 YIN。

两个结果都转换到统一 A4=440 Hz 的 MIDI/cents 表示。最终单音候选按 YIN 置信度、61 键谐波显著度、基频或低阶泛音存在性以及相邻八度竞争结果联合选择。低频 YIN 与谐波模板一致时优先采用低频结果；发生一倍频或二倍频冲突时，比较奇偶泛音和低阶谐波覆盖，不能只按最大峰决定八度。

单音识别仍需通过幅度门、削波门和音调性门。人声、拍手和宽带噪声不能因为某个瞬时 YIN 谷值就产生琴键事件。

## 61 键谐波显著度

频谱使用 4096 点 Hann 窗和 1024 点 hop；每两个 hop 更新一次多音结果，即约 85 ms 一次。对每个 MIDI 36--96 预计算基频及 2--8 次谐波的位置和权重。

每个琴键显著度包含：

- 基频附近的插值局部峰；
- 2--8 次谐波中落在分析带宽内的局部峰；
- 各峰相对所在频段噪声底的突出度；
- 钢琴高次谐波允许的小范围非理想偏移；
- 缺少预期低阶谐波、只有单个孤立峰或与更低琴键完全重合时的惩罚；
- 与相邻半音、上下八度候选的竞争结果。

C2 附近即使基频分辨率有限，也可以通过二至八次谐波的整体间距恢复具体低音。模板不能仅凭某个高次谐波产生候选；低音至少需要多个符合整数倍关系的峰，或低频 YIN 与谐波模板一致。

## 最多四键的稀疏分解

多音识别不使用固定和弦模板作为入口，而是对 61 个显著度执行最多四轮稀疏选择：

1. 选择当前显著度最高且通过绝对噪声、相对强度和局部峰门限的琴键；
2. 从剩余频谱证据中扣除该琴键模板可解释的谐波能量；
3. 重新计算剩余琴键显著度；
4. 达到四键、剩余证据不足或新增候选不能提供独立峰时停止。

一个物理峰只能由一个候选拥有。高次谐波不能同时作为另一个琴键的全部证据；相邻半音必须各自具有可区分的局部峰或跨多个谐波的一致支持。结果输出排序后的具体 MIDI，和弦名称仅根据最终琴键集合派生用于显示，不参与是否接纳该集合。

## 逐键时间跟踪

识别器为 MIDI 36--96 维护 61 个独立状态和一个 64 bit 活动掩码。每个键具有激活分数、连续候选帧数、连续缺失帧数、起音时间、置信度和速度估计。

- 正常候选连续两个多音更新周期后激活；
- 弱低音或只有一路麦克风可用时允许要求三个周期；
- 新的幅度起音可加快已有高置信候选的确认，但不能绕过音高门；
- 琴键连续缺失两个周期后释放；短暂泄漏或频谱凹陷不会立即释放；
- 同一 MIDI 在明确新起音且已经满足最小重触发间隔时，生成一次释放再起音；
- 同一集合持续存在时只更新置信度，不制造重复起音；
- 超过四个可信候选时不截取最响的四个冒充结果，而是保持上一可信集合或输出不确定状态。

稳定输出包含活动掩码、排序后的最多四个 MIDI、逐键速度、逐键置信度、集合置信度、时间戳、麦克风降级状态和单调递增的状态编号。

## 自动增益和状态恢复

正式识别允许 ES7210 在 18、21、24、27、30 dB 五档间调整：

- 当前有效分析通道连续削波时立即降低一档；
- 两路都健康但仅一路削波时，先移除削波通道，不因坏路降低健康路的有效信号；
- 有效信号峰值持续过低且 SNR 不足时缓慢升高一档；
- 每次变化设置稳定间隔，防止来回振荡；
- 设定失败时保留原档并记录错误，不重启采集任务。

增益变化后清空 YIN、FFT、稀疏分解和时间跟踪短期历史，按增益比缩放噪声估计，重新填满分析窗口后才恢复结果。麦克风质量切换只清除依赖旧通道的短期候选，不清除已经确认且仍被新通道支持的活动琴键。

## MusicLink v2

物理链路使用两端源码当前一致的配置：UART1、115200 baud、8N1、无流控。接线为 P4 GPIO0/TX 到 S3 GPIO2/RX，S3 GPIO1/TX 到 P4 GPIO1/RX，并共地。P4 保持 50 ms 主轮询；旧文档中的 460800、旧 GPIO 方向和旧 H7 针号全部改为当前网表定义。

S3 上电先发送兼容 v1 的 `hello`，增加 `capabilities:["note_set_v2"]`、`midi_min:36`、`midi_max:96` 和 `max_polyphony:4`。新 P4 使用以下命令开始 v2 会话：

```json
{"cmd":"start","sid":12,"protocol":2,"profile":"performance"}
```

未请求 v2 的旧 P4 继续获得现有 v1 单音事件。v2 会话使用完整状态快照：

```json
{"v":2,"type":"notes","seq":108,"sid":12,"state_id":35,"ts_ms":4260,"midis":[48,52,55],"velocities":[91,78,84],"confidences":[0.950,0.890,0.920],"set_confidence":0.910,"degraded_mic":false}
```

协议约束如下：

- 三个数组长度相同，长度为 0--4；
- MIDI 严格递增、无重复且位于 36--96；
- velocity 位于 1--127；空集合没有 velocity；
- 置信度为有限的 0--1 数值，不允许 NaN/Inf；
- `state_id` 在一个 `sid` 内从 1 单调递增；
- 空数组表示全部琴键释放；
- 状态变化立即替换 S3 的“最新待确认状态”，旧未发送状态可以被完整新状态覆盖；
- 控制/status 帧和琴键状态使用独立队列，pitch 与诊断帧可丢弃，琴键最新状态不能因 FIFO 满而永久丢失。

P4 的轮询带回已接收状态编号：

```json
{"cmd":"poll","sid":12,"ack_state_id":35}
```

S3 在状态被确认前重复最新快照。P4 对相同 `sid/state_id` 幂等处理，因此重传不会产生重复事件。状态确认后，S3 只在活动集合、明确的同音重触发或麦克风降级状态变化时生成新快照。持续音内部可以更新置信度，但不能因浮点置信度或 RMS 抖动不断增加 `state_id`；velocity 和逐键置信度在该键本次起音确认时锁定，直到释放或重触发。

## P4 集合差分和评分接入

P4 协议解析器同时接受 v1 和 v2，并严格校验数组、范围、有限浮点数、`sid`、`seq` 和 `state_id`。收到新的有效集合后：

1. 与当前活动集合比较；
2. 使用 S3 的同一 `ts_ms` 先为消失的 MIDI 生成 `note_off`；
3. 再为新增 MIDI 生成 `note_on`；
4. 仍然存在的 MIDI 不重复起音，只更新内部质量信息；
5. 将生成的逐键事件送入现有 `scoring_service_handle_audio_s3_event` 和 performance recorder。

同一个快照产生的多个琴键事件共享时间戳，使 P4 将它们视为同时和弦。S3 与 P4 的绝对时钟不要求同步；P4 以会话首个 S3 时间戳建立本地偏移，并保留 S3 相对时间间隔，从而降低 50 ms 轮询抖动对节奏评分的影响。

发生以下任一情况时，P4 先为全部活动琴键生成一次释放，再清空集合：

- `sid` 改变；
- S3 重新发送 `hello`；
- 音乐链路超过在线超时；
- P4 停止流或切换输入源；
- 收到显式空集合。

P4 的事件队列必须能容纳一次四键集合完全替换所需的最多八个事件。队列不足时不能只投递一半集合；应先记录错误并通过下一次完整状态快照恢复。

## 诊断 PCM 采集

诊断采集默认关闭，并与正式识别输出互斥。采集命令和数据块复用 MusicLink，但有两种互斥台架：整机调试时由 P4 作为链路主机，实验室调参时断开 P4 并由 USB-UART 适配器和电脑脚本直接连接 S3 GPIO1/2。P4 和电脑脚本使用相同命令、块编号和 CRC 规则，不能同时连接。发出带长度上限的采集命令后，S3：

1. 报告 `capture_pending` 并停止正式琴键状态更新；
2. 使用有界缓冲采集 500 ms、24 kHz、16 bit、双声道交错 PCM，共 48000 bytes；
3. 停止采集后按带序号和 CRC32 的小块传输，不与实时 PCM 同传；
4. 接收端校验块序号、块 CRC 和整段 CRC，重组标准双声道 WAV；
5. P4 将完整数据写入已有可写存储后封装 WAV；若没有可写存储，在发起采集前返回错误。电脑台架由配套脚本直接写 WAV；
6. 完成或取消后清空缓冲、重新校准噪声和识别历史，再恢复正式模式。

采集缓冲只在诊断命令期间分配。分配失败时返回明确错误并保持正式识别运行。传输期间琴键结果处于明确暂停状态，P4 不得把旧活动集合继续计入评分。

## 日志与错误处理

启动日志报告采样格式、61 键范围、双麦槽位、增益、协议能力和 DSP 预算。周期诊断报告：

- 两路 RMS、peak、clip、噪声门、分频段 SNR 和质量状态；
- 当前增益、参与融合的通道和降级原因；
- YIN 候选、61 键最高候选、最终活动集合和集合置信度；
- 每路 FFT、YIN、稀疏分解和总 DSP 耗时；
- capture drop、DSP deadline miss、UART tx drop、未确认状态和 P4 ack；
- 任务栈余量、采集队列深度和缓冲耗尽次数。

两路都无效、DSP 超时或内存不足时，S3 输出空集合或保持上一集合到短暂容错期结束，随后释放，绝不从无效数据猜音。任何降级均通过状态或日志可见。

## 测试策略

### 可移植算法测试

把 61 键显著度、稀疏分解和时间跟踪整理为不依赖 FreeRTOS/ESP-IDF 的纯 C 单元。测试覆盖：

- C2--C7 的 61 个标准频率及小范围 cents 偏移；
- 不同谐波强弱、缺失基频和奇偶泛音差异；
- 相邻半音、八度、五度和宽音程；
- 任意双音、三音、四音及强弱不均组合；
- 噪声、静音、人声近似谱、拍手、削波和单路损坏；
- 候选出现/消失、重复同音、集合完全替换和超过四音的拒绝。

### 真实 WAV 回归集

使用诊断模式采集两路 WAV，并用清单记录设备、音量、距离、MIDI 集合和演奏时间。最低覆盖：

- 61 个单音，每个至少三个力度或距离条件；
- 低、中、高音区的相邻半音、八度、五度和宽双音；
- 大、小、增、减、sus 以及不同转位的三键集合；
- 常见七和弦和任意四键集合；
- 静音、人声、敲击和环境噪声；
- 分别遮挡、断开、削波 MIC1 和 MIC2。

回归工具输出逐文件期望/实际集合、逐键置信度、首次确认延迟、释放延迟、精确集合准确率、误触发和降级状态。参数调整不能只改善少数示例而降低整套数据集结果。

### S3 与 P4 协议测试

S3 测试验证最新状态覆盖、重传、ack、会话复位和队列优先级。P4 测试验证合法/非法 v2 JSON、重复状态、乱序状态、集合差分、同时八事件、链路超时和重启释放。双板测试模拟丢帧、重复帧、队列满和单向链路故障，确保没有重复起音、遗漏释放或卡音。

## 验收顺序

1. 两个工程分别构建通过，S3 DSP 无 deadline miss，P4 无协议解析错误。
2. 完成 61 个单音 WAV 回归并达到不低于 95%。
3. 完成双音/三音回归并达到不低于 90%。
4. 完成四音回归并达到不低于 80%。
5. 静音、人声和敲击误触发率低于 2%。
6. 正常确认延迟主要为 180--300 ms，释放和换音不产生卡音。
7. 分别使一块麦克风失效，另一块仍维持识别且协议结构不变。
8. 验证 P4 对完整和弦产生同时间戳的逐键事件，并能进入现有跟谱和评分。
9. 验证 S3/P4 任一端重启、链路中断和帧重传后均不会重复或遗留活动琴键。

## 实施边界

实施将修改两个工程，但分别提交：

- `smartscore_s3_audio`：预处理、双麦质量、YIN、61 键显著度、稀疏分解、时间跟踪、MusicLink v2、诊断采集和测试；
- `smartscore_wt99_p4`：音乐协议解析、可靠 ack、琴键集合差分、现有评分入口接入、协议测试和文档。

P4 工作区已有与本任务无关的未提交修改。实施时只修改音乐链路、协议、评分接入和对应测试/文档文件，不覆盖、暂存或提交其他现有改动。

# 现场音符识别测试档设计

## 目标与范围

在 P4 的“音符识别测试”页面中提高双音和三和弦的显示成功率，适应展示现场的稳定背景噪声、音符力度不均和短暂反射声。调优只在该测试页面会话中生效；跟谱、评分及其他 Audio S3 使用场景继续使用当前严格识别参数。

本次不修改 UI 布局、不修改 UART 物理接口和现有消息格式的含义，也不改变单音、评分、MIDI、语音助手、网络或小程序逻辑。

## 方案

沿用 P4 到 Audio S3 的 `start` 会话命令，新增可选的 `profile` 字段：

- 普通调用仍发送现有命令，Audio S3 使用 `strict` 档。
- P4 音符识别测试页面发送 `profile=demo`。
- `stop`、链路重启或新的普通 `start` 均恢复 `strict` 档，防止宽松参数泄漏到正式业务。
- 旧固件遇到不认识的可选字段仍可按原 `start` 命令工作，协议保持向后兼容。

Audio S3 在检测任务中读取当前档位，并在档位切换时清空分类器稳定历史，避免严格档和演示档的历史帧混合。识别档位由 UART 控制任务写入、检测任务读取；WebSocket、UI 和评分任务不参与。

## 演示档参数

严格档参数保持不变。演示档使用以下参数：

| 判定项 | 严格档 | 演示档 |
| --- | ---: | ---: |
| 双音置信度 | 0.58 | 0.50 |
| 大/小三和弦置信度 | 0.66 | 0.60 |
| 有效音级相对门限 | 0.18 | 0.14 |
| 弱基频相对最强基频门限 | 0.04 | 0.025 |
| 双音允许的最多活动音级 | 4 | 5 |

演示档不降低绝对噪声底倍数，也保留当前 5 帧中 3 帧一致的稳定投票。这样可以接纳力度较弱的第二、第三个真实音符，同时继续拒绝低于动态噪声底的随机峰值。若候选峰缺少独立局部峰或被判定为强音的明确泛音，仍不作为独立音符显示。

## 数据流与状态恢复

1. 用户进入 P4 音符识别测试页面。
2. P4 创建测试会话并发送 `start + sid + profile=demo`。
3. Audio S3 切换演示档、重置稳定历史并继续通过原有 `poly` 消息发送结果。
4. 用户退出页面时 P4 发送 `stop`。
5. Audio S3 立即恢复严格档并再次重置稳定历史。
6. 异常重连后，P4 根据当前会话重新同步；没有测试会话时默认严格档。

## 日志与错误处理

- Audio S3 每次档位改变打印一次 `recognition profile: strict/demo`。
- 缺失或未知 `profile` 一律回退 `strict`，并对未知值打印警告。
- P4 测试页面启动失败时保持现有错误显示，不在本地伪造双音结果。
- 退出、停止或会话替换必须恢复严格档，即使前一会话异常中断。

## 验收

- 测试页面中，不同力度的两个音和常见大/小三和弦比当前更容易稳定显示。
- 稳定背景噪声下不持续产生无演奏的虚假音符。
- 退出测试页面后，Audio S3 日志显示恢复 `strict`。
- 正式跟谱和评分仍使用原阈值，行为不变。
- UART 的 `poll`、`ping`、普通 `start`、`stop` 和现有上行消息继续兼容。

本次只做源码修改和差异检查，不执行编译或硬件测试。

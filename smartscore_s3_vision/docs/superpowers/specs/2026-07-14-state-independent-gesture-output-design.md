# SmartScore 手势输出与录像状态解耦设计

## 目标

只要手势识别成立，就立即向串口输出对应的纯数字动作编号，不再因为当前处于 `IDLE`、`RECORDING`、`FINISHED` 或 `SCORE_REQUESTED` 而丢弃输出。

动作映射保持不变：

- 向右挥手：`1`
- 向左挥手：`2`
- OK：`3`
- 五指张开：`4`
- 点赞：`5`

## 核心设计

手势引擎只负责判断“是否识别到一个可输出的动作”，不再检查录像状态。满足置信度、轨迹、冷却和重新武装条件后，直接返回动作编号。

应用层收到动作编号后先无条件输出纯数字，再根据当前录像状态决定是否执行附带操作：

- 动作 `3`：总是输出 `3`；仅在尚未录像时尝试创建 SD 会话并进入 `RECORDING`。
- 动作 `4`：总是输出 `4`；仅在 `RECORDING` 时开始停止录像流程。
- 动作 `5`：总是输出 `5`；仅在 `FINISHED` 时进入 `SCORE_REQUESTED`。
- 动作 `1`、`2`：总是输出数字，不改变录像状态。

这样可以保证网页识别结果、诊断日志与纯数字串口事件一致，同时避免乱序动作破坏 SD 录像会话。

## 单次触发

保留现有单次触发规则：同一手势持续停留在画面中时只输出一次。动作触发后进入冷却；检测到手移出、无手或不同有效手势后重新武装，才允许下一次输出。

状态限制不再参与识别结果，因此删除 `state_not_allowed` 对动作输出的拦截。诊断信息继续显示当前状态，但状态只说明附带录像操作是否执行。

## 错误处理

- 动作 `3` 的 SD 会话创建失败时，数字 `3` 已经输出，应用保持非录像状态并记录错误。
- 在非录像状态识别到动作 `4` 时，输出 `4`，但不执行停止流程。
- 在非完成状态识别到动作 `5` 时，输出 `5`，但不强制改变状态。
- 网页预览、AI 工作线程和摄像头参数保持不变。

## 验证

1. 使用 ESP-IDF 5.4 完整编译。
2. 在 `IDLE` 下分别识别 OK、五指和点赞，确认串口分别输出纯数字 `3`、`4`、`5`。
3. 在 `RECORDING` 下分别识别 OK、五指和点赞，确认同样输出对应数字。
4. 确认 `IDLE` 下的五指不会错误启动停止录像流程，点赞也不会强制进入评分状态。
5. 持续保持同一手势，确认只输出一次；移开手再做相同手势，确认能够再次输出。
6. 确认左右挥手仍输出 `1`、`2`，且不受录像状态影响。
7. 检查诊断日志中的动作编号和纯数字输出一致。

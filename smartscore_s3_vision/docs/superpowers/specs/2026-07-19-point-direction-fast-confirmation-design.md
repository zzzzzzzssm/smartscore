# 左右指快速确认与 INT8 推理设计

## 目标

修复板端已经识别出 `point_left` 或 `point_right`、但因 90% 门槛和 3/4 投票而无法输出动作的问题，同时缩短自定义左右指模型的单次推理时间。乐鑫官方 `ok`、`five`、`like` 手势及动作 3、4、5 的优先级和处理路径保持不变。

## 已确认问题

- INT16 输出后处理已经修正，板端日志能够给出有区分度的结果，例如 `point_left conf=85% margin=72%`。
- 当前 90% 置信度门槛会拒绝上述强结果。
- 当前自定义模型一次推理约 1.75 秒，3/4 投票可能需要保持动作五秒以上。
- 训练导出脚本支持 ESP32-S3 INT8 量化，并能在替换板端模型前计算量化准确率、宏平均 F1 和浮点模型预测一致率。

## 触发规则

1. 强结果：类别为 `point_right` 或 `point_left`，置信度至少 80%，且第一、第二名分差至少 45%，单次结果即可确认。
2. 普通结果：类别为左右指之一，置信度至少 65%，且分差至少 20%，连续两次方向相同才确认。
3. `other`、无手、多手、控制区外或方向改变时清空普通结果的连续计数。
4. 保留现有动作冷却和重新解锁逻辑，保证一次动作只输出一次。
5. 动作映射不变：`point_right -> 1`，`point_left -> 2`。

## INT8 模型替换门槛

使用八人数据对应的 `training_data/processed_v2/manifest.csv` 和当前最终 ONNX 模型导出 INT8 ESP-DL 模型。INT8 模型只有同时满足以下条件才替换当前 INT16 模型：

- 量化评估准确率不低于 98%；
- 量化宏平均 F1 不低于 98%；
- 与浮点模型预测一致率不低于 98%；
- 输出类别顺序仍为 `point_right`、`point_left`、`other`；
- 导出文件能够由当前 ESP-DL 3.3.7 读取。

任一条件不满足时保留 INT16 模型，只应用快速确认规则，不以降低离线准确率换取速度。

## 板端实现

- 自定义后处理继续按模型的真实输出类型和量化指数读取 logits；INT8 与 INT16 共用同一安全 Softmax 实现。
- 启动日志打印实际输出数据类型和指数，便于确认烧录的是 INT8 还是 INT16 模型。
- 不改摄像头、SD 卡、每三秒拍照、会话状态机和官方手势识别代码。
- 不增加逐帧大量日志；沿用现有低频 AI 结果日志检查置信度、分差和触发原因。

## 验收

- 强左右指结果一次推理即可分别输出纯数字 `1` 或 `2`。
- 普通左右指结果连续两次一致后输出，方向变化不会累积错误票数。
- 同一动作在手未离开或未改变前不重复输出。
- 官方 `ok`、`five`、`like` 仍分别输出 `3`、`4`、`5`。
- INT8 未通过离线指标时，工程仍使用原 INT16 模型并可正常构建。
- 用户负责执行 ESP-IDF 固件编译和烧录；本次修改不代为编译固件。

# SmartScore 摄像头实时预览与识别诊断设计

## 目标

在保留现有摄像头、手势 AI、SD 记录和动作状态机的前提下，让 ESP32-S3 建立无需密码的 Wi-Fi 热点，并通过浏览器实时查看摄像头画面及手势识别状态。该功能用于确认取景、距离、光线、检测框、分类标签和置信度，从而定位当前“检测到手但动作不触发”的具体原因。

## 用户入口

- ESP32-S3 启动开放热点 `SmartScore-Cam`，不设置密码。
- 手机或电脑直接连接该热点，访问 `http://192.168.4.1`。
- 页面提供约 3–4 FPS 的实时画面，并显示手部检测框和识别状态。
- 热点仅用于本地预览，不提供互联网连接。
- 为限制内存、带宽和 CPU 占用，预览服务只支持一个活动客户端。

## 模块边界

新增独立的预览模块，负责以下功能：

- 初始化 NVS、网络接口、默认事件循环、Wi-Fi SoftAP 和 HTTP 服务。
- 在 PSRAM 中保存主循环发布的最新 JPEG。
- 保存最新 `HandObservation`、当前会话状态和最后触发动作的轻量快照。
- 提供首页、JPEG 流和 JSON 状态接口。

现有模块职责保持不变：

- `CameraDriver` 仍是唯一摄像头初始化与取帧封装。
- `HandAi` 仍只负责检测和分类。
- `GestureEngine` 仍只负责动作确认。
- `SdStorage` 仍只负责会话和照片写入。
- `app_main` 负责把已经取得的 JPEG 与 AI 结果发布给预览模块。

## 画面数据流

摄像头只能由现有主循环取帧。禁止 HTTP 任务再次调用 `esp_camera_fb_get()`，避免两个消费者竞争帧缓冲。

主循环取得 JPEG 后，在归还 `camera_fb_t` 前，将当前 JPEG 复制到预览模块的 PSRAM 最新帧缓冲。HTTP 流任务先在短临界区内把最新帧复制到自己的 PSRAM 发送缓冲，再释放锁并通过网络发送；网络慢不会长时间阻塞 AI 主循环。

预览帧大小设置明确上限。超过上限的 JPEG 被跳过并限频告警，不影响 AI、SD 或下一帧。无客户端时仍可更新最新帧，但 HTTP 任务不做重复发送。流速限制为约 3–4 FPS，不追求高帧率。

## 识别状态与网页叠加

每次 AI 推理后发布以下状态：

- 是否检测到手；
- 手框坐标和手部检测置信度；
- 是否位于控制区；
- 分类标签和手势置信度；
- 当前会话状态；
- 最后一次动作编号。

浏览器通过 JSON 接口定期获取状态，并按原始画面坐标比例在视频上叠加检测框。状态面板使用文字明确区分“未检测到手”“手在控制区外”“分类置信度不足”和“手势已满足触发条件”，避免仅靠串口猜测。

原始模型标签需要保留到诊断状态中，包括 `one`、`five`、`ok`、`no_gesture` 等；内部 `StaticGesture` 映射继续服务动作状态机，不替代原始标签。

## 稳定性与错误处理

- Wi-Fi、网络接口或 HTTP 服务初始化失败时，只记录错误并禁用网页预览；摄像头、AI 和 SD 功能继续运行。
- 预览缓冲必须从 PSRAM 分配，失败时禁用画面流但保留串口和识别功能。
- 发布帧和状态使用短锁，不允许在持锁期间执行网络发送、JPEG 解码或模型推理。
- HTTP 连接断开后释放客户端发送缓冲并允许下一客户端连接。
- 保留现有主循环调度让步，不提高 AI 推理频率，避免重新引入任务看门狗问题。
- 开放热点无访问控制，附近设备均可连接；该取舍由用户明确选择。

## 构建影响

主组件增加 ESP-IDF 的 `nvs_flash`、`esp_netif`、`esp_event`、`esp_wifi` 和 `esp_http_server` 依赖。ESP-IDF 5.4 安装中的官方 Wi-Fi 库必须完整可用；若工具链因旧 Git 工作树路径导致子模块缺失，应先恢复官方子模块，再执行项目构建。

## 验证

1. 使用 ESP-IDF 5.4 完整构建，并确认应用分区仍有足够空间。
2. 启动后确认热点 `SmartScore-Cam` 可发现、无需密码可连接，且 `192.168.4.1` 页面可打开。
3. 确认网页画面方向、亮度和取景正确，视频更新期间 AI 与 SD 不崩溃。
4. 将手移入画面，确认网页检测框、检测置信度、原始分类标签和分类置信度随动作变化。
5. 依次测试 IDLE 下的挥手和 OK、RECORDING 下的五指张开、FINISHED 下的点赞，并确认最后动作编号更新。
6. 断开并重新连接一个客户端，确认发送缓冲释放且服务恢复。
7. 连续运行时不得出现任务看门狗复位；少量摄像头 `FB-OVF` 允许出现，但网页、AI 和状态机必须继续运行。

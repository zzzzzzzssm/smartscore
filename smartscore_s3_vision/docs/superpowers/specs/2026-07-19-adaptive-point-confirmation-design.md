# 左右指自适应确认设计

## 背景与诊断

实机日志显示，TinyPointNet 能输出左右方向，但相邻帧受 Hand Detect 检测框波动影响，方向概率会摆动。右指常落在 62%～86%，被当前统一 88% 门槛拦截；左指较容易达到高概率，因此当前表现同时存在漏识别、方向不稳定和左右响应不均衡。

本次只校准动作 1、2。乐鑫官方 OK、五指张开、竖大拇指以及动作 3、4、5 的分类、优先级和触发规则保持不变，不重新训练模型。

## 触发策略

方向模型继续只处理控制区内、Hand Detect 仅检出一只手且检测置信度至少 50% 的画面。

- 右指普通候选：`point_right` 概率至少 65%，且第一、二名概率差至少 30%。
- 左指普通候选：`point_left` 概率至少 85%，且第一、二名概率差至少 30%。
- 高可靠候选：方向概率至少 97%、概率差至少 90%，同时 Hand Detect 置信度至少 70%。高可靠候选允许单帧触发。
- 普通候选：必须在 1800 ms 内再次得到同一方向，第二次才触发。
- 出现相反方向候选时，旧方向计数清零，并从新方向的第一次候选开始计数。
- 短暂的无手、弱手或多手结果不立即删除第一次候选，但候选超过 1800 ms 自动失效。
- 手明确离开控制区、出现官方控制手势、动作成功触发或进入冷却时，清空方向候选。

触发成功后仍只输出一次纯数字：右指输出 `1`，左指输出 `2`，并沿用现有冷却及重新解锁机制。

## 代码边界

- `HandAi` 负责把满足普通门槛的原始方向结果交给手势引擎，不承担跨帧状态。
- `GestureEngine` 单独维护动作 1、2 的候选方向、次数和时间；官方静态手势继续使用现有单帧路径。
- `vision_config.hpp` 集中保存左右普通门槛、高可靠门槛、概率差、确认次数和超时时间。
- 串口诊断增加方向确认进度，例如 `point_confirm=1/2`，但不增加逐帧大段日志。

## 验证

- 单元测试覆盖：右指两次确认、左指两次确认、高可靠单帧触发、相反方向重置、短暂漏检保留、超时失效、触发后不重复输出，以及官方动作 3/4/5 行为不变。
- 运行 `git diff --check` 和 ESP-IDF 全量构建。
- 创建独立实现提交，不包含用户的 `.vscode/` 和 `components/` 未跟踪目录。
- 实机验收以串口日志为准：普通方向约 1.3～1.5 秒触发，高可靠方向约 0.7 秒触发；同一次动作只输出一个编号。

## 风险与后续

两次确认会增加普通动作延迟，但比直接降阈值更能抑制误触发。若实机仍频繁方向反转，说明训练裁剪图与板端检测框存在域差异，下一步应保存实机困难样本，按人员隔离重新训练，而不是继续无依据降低阈值。

# 更小更快左右指模型与板端稳健触发设计

## 目标

在保留乐鑫官方动作 3、4、5 和每 3 秒拍照逻辑的前提下，修正动作 1、2 当前低置信度手框与单帧宽松触发造成的误识别，并用现有 P001～P008 数据训练比 MobileNetV3-Small 1.0 更小、更快的本地方向分类模型。

## 验收门槛

候选模型只有同时满足以下条件才允许替换当前固件模型：

- 八折整人留出准确率不低于 90%。
- 八折整人留出宏平均 F1 不低于 90%。
- 在验证集自动选择动作阈值后，`other` 误触发率不高于 2%。
- 最差人员准确率不低于当前 MobileNetV3 基线的 80.65%。
- 量化后准确率和宏平均 F1 均不低于 90%，相对浮点宏平均 F1 下降不超过 3 个百分点，预测一致率不低于 97%。
- ESP-DL 导出过程没有不支持算子、负移位或其他部署异常。
- `.espdl` 文件小于当前 3,313,488 字节模型，理论运算量低于当前模型；板端实际速度最终以烧录日志为准。

任一门槛失败时保留当前模型，并继续测试下一个候选；所有候选都失败时不以低准确率模型替换可用基线。

## 候选方案

按预期板端速度从快到慢测试：

1. 96×96 输入的普通卷积 TinyPointNet。仅使用 ESP-DL 成熟支持的 Conv、ReLU、全局平均池化和分类头，避免深度卷积的 INT8 负移位风险；通过 MobileNetV3 教师蒸馏提高小数据集泛化能力。
2. 96×96 输入的 `mobilenetv3_small_050.lamb_in1k`。使用 ImageNet 预训练权重，在 TinyPointNet 未达门槛时作为低风险候选。
3. 96×96 输入的 `mobilenetv3_small_075.lamb_in1k`。只在前两个候选未达精度门槛时训练。

优先尝试 INT8；INT8 不可部署或精度不合格时尝试 INT16。模型选择依据是“满足全部门槛的候选中预计板端速度最快”，不是单纯选择离线分数最高者。

## 数据和评估

- 继续使用 `training_data/processed_v2/manifest.csv`，严格按人员进行八折留一验证。
- 从训练清单排除 52 张 `landmark_direction_disagrees` 样本，不把已知方向冲突继续当作正确标签训练。
- 水平翻转时同步交换左右类别；保留亮度、轻微旋转、平移、模糊和遮挡增强。
- 训练脚本支持可配置输入尺寸和模型名，保存每折指标、混淆矩阵、阈值、参数量、MACs、训练轮数、随机种子和最终校验值。
- 量化校准集覆盖八个人和三个类别，量化评估样本与类别保持均衡。

## 板端输入和触发

- 官方动作 3、4、5 仍使用当前 Hand Detect 与官方 Hand Gesture Recognition 路径，不提高它们的检测门槛。
- 自定义动作 1、2 增加独立的手框置信度门槛，默认 50%；低于门槛不运行方向模型，避免 38% 弱检测框触发。
- 自定义裁剪扩边与训练增强一起验证，不再把 MediaPipe 关键点框和 ESP-DL 检测框错误地视为同一种框。
- 左右指继续支持一次模型推理触发以控制延迟，但部署阈值由整人留出验证自动选择，不再固定使用未经验证的 55%。
- 保留控制区、单手限制、动作编号、冷却及离手/变手势后重新触发规则。
- 启动日志输出模型架构、输入尺寸、量化类型和部署阈值；周期日志继续输出置信度、分差、手框置信度和耗时。

## Git 和回退

先提交当前可运行的 MobileNetV3-Small 1.0 状态作为独立检查点，再修改训练和固件。训练产物放入独立目录，只将最终模型、指标摘要、源代码和中文说明纳入 Git；不提交虚拟环境、全部中间权重、用户的 `.vscode/` 或本地 `components/` 目录。

最终接入前保留当前模型副本及 SHA-256。若构建失败、模型加载失败或量化指标失败，自动恢复到检查点，不留下半接入状态。

## 验证与交付

依次运行训练脚本单元测试、数据清单审计、八折验证、最终训练、ONNX 数值核对、INT8/INT16 量化评估、ESP-DL 模型检查和 `idf.py build`。最终中文说明记录入选或淘汰原因、模型大小、离线指标、预计速度、构建结果，以及需要用户在 COM8 板端复测的动作 1～5 和实际推理时间。

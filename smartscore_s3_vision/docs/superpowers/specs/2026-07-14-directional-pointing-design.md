# SmartScore 左右指替代挥手设计

## 目标

删除现有左右挥手跟踪，改为静态的食指水平指向动作：

- 食指向右输出动作 `1`。
- 食指向左输出动作 `2`。
- 与 OK、五指张开、点赞相同，第一次有效识别立即触发一次；手离开控制区并经过现有冷却后才能再次触发。
- 动作 `3`、`4`、`5` 及其录像状态逻辑保持不变。

## 模型限制与方案

官方 `hand_gesture_recognition` 模型包含 `one`，但没有独立的 `point_left` 或 `point_right` 类别。因此不能直接根据普通分类结果确定方向。

采用双向旋转确认：从官方手部检测框提取固定大小的方形 RGB 手部图像，分别顺时针和逆时针旋转 90 度，再交给官方手势分类模型判断 `one`。水平食指被旋转成模型更熟悉的竖直单指姿态：

- 原图向右指，逆时针旋转后应更接近 `one`，输出 `1`。
- 原图向左指，顺时针旋转后应更接近 `one`，输出 `2`。

至少一侧的最高分类为 `one` 并达到单指置信度门槛，而且其得分比另一方向高出规定差值时才触发；结果接近或置信度不足时不输出，避免猜测方向。某一旋转方向的最高分类不是 `one` 时，该方向的单指得分按零处理。

## 数据流

1. 摄像头继续提供 VGA JPEG，AI 工作任务解码为长期复用的 RGB888 缓冲。
2. 官方手部检测器输出最佳手部框和检测置信度。
3. 普通分类继续识别 OK、五指张开和点赞。
4. 普通分类不是动作 `3`、`4`、`5` 时，对同一手部框执行左右两种 90 度旋转分类。
5. 双向结果满足方向判定条件时，生成 `POINT_RIGHT` 或 `POINT_LEFT` 观察结果。
6. `GestureEngine` 使用现有单次触发、冷却和重新武装机制输出动作编号。

## 资源与性能

- 删除 `FastWaveTracker` 任务、队列、JPEG 副本和 96×72 跟踪帧缓冲。
- 新增两个固定的 128×128 RGB888 旋转缓冲，共约 96 KB，放置在 PSRAM；运行过程中不反复申请内存。
- 无手时只运行检测；普通静态动作只需原有分类。
- 只有普通分类未识别成动作 `3`、`4`、`5` 的手部才运行两次旋转分类。方向动作会比 OK 等动作多一些分类耗时，但不再依赖多帧运动轨迹。
- 继续保持网页和 Wi-Fi 关闭、CPU 240 MHz、PSRAM 80 MHz 和性能优化配置。

## 判定与防误触

- 手部检测必须达到现有检测门槛并位于控制区。
- 旋转后的最高分类必须为 `one`，且达到独立的方向单指置信度门槛。
- 两个方向的 `one` 得分差必须达到最小优势值；否则记录为方向不确定，不触发动作。
- 方向动作与其他三个静态动作一样，一次有效结果即可触发，不增加保持时间或连续投票。
- 触发后必须先看到无手或手离开控制区，再按现有冷却规则重新武装。

## 日志与验证

串口日志增加左右旋转的标签、置信度、得分差、最终方向和推理耗时，纯数字动作输出规则保持不变。

验证内容：

1. 完整构建通过，应用分区不溢出。
2. 启动后无快速挥手任务、网页或 Wi-Fi 服务。
3. 食指水平向右时输出一次 `1`，向左时输出一次 `2`。
4. 保持同一指向不会连续输出；手离开后可重新触发。
5. 竖直单指、握拳、手掌静止以及方向置信度接近时不输出 `1` 或 `2`。
6. OK、五指张开、点赞仍分别输出 `3`、`4`、`5`。
7. 记录实际方向识别耗时和内存余量，确认无崩溃、看门狗复位或持续内存下降。

# 官方手势候选保护设计

## 问题

实机日志证明动作编号映射正确：官方模型识别到 `like` 时会输出 `5`。错误输出 `2` 的原因是，同一个竖大拇指姿势在部分帧没有成为官方分类第一名，随后被方向模型误判为 `point_left`，并被统一 60% 单帧门槛立即触发。

## 规则

- 乐鑫官方 Hand Gesture Recognition 从 Top-1 改为返回 Top-3 分类结果，不更换模型。
- 第一名仍按原门槛 55% 触发 `ok/five/like`，因此动作 3、4、5 的输出编号和速度保持不变。
- 在进入自训练方向模型前，检查 Top-3 中的 `ok/five/like`。任何保护类别置信度达到 25% 时，本帧禁止输出动作 1、2。
- 被保护拦截的帧标记为 `official_veto_<label>`，串口输出实际候选置信度，便于实机复核。
- 如果 Top-3 中没有达到保护门槛的官方控制类别，方向模型继续使用左右统一 60% 置信度、30% 分差和单帧触发。
- Hand Detect、控制区域、冷却、防重复和 SD 拍照逻辑不变。

## 验证

- 为官方候选保护判断编写宿主测试：保护类别达到门槛时拦截，低于门槛时放行，无关类别不拦截。
- 保留现有方向单帧状态机测试和 Python 训练工具测试。
- 运行 `git diff --check` 与 ESP-IDF 构建，并创建独立实现提交。

## 后续

该保护解决官方模型与方向模型之间的同帧抢判。下一轮重新训练方向模型时，仍应把竖大拇指、OK 和五指张开加入 `other` 困难负样本，从模型层面减少误判。

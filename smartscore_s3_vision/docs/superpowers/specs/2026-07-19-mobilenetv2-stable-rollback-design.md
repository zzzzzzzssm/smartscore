# MobileNetV2 稳定方向模型回退设计

## 目标

将当前偏向 `point_left` 的 TinyPointNet INT8 模型替换为此前实机认可的 MobileNetV2-0.5 INT16 模型。优先恢复左右指识别稳定性，接受推理速度比 TinyPointNet 慢。

## 固定模型

- 来源：`training_artifacts_mnv2_fast/final/point_direction_int16.espdl`
- 结构：MobileNetV2-0.5
- 量化：INT16
- 输入：RGB、NHWC `1×128×128×3`（ESP-DL 板端张量布局）
- 类别：`0=point_right`、`1=point_left`、`2=other`
- 文件大小：1,636,496 字节
- SHA-256：`31b344a6f94140cfb689309ad99df30cfdbdd2d53d95fad10f4c622a5c10fd2a`
- 1200 张量化评估集准确率：95.75%

不重新训练，不使用 MobileNetV3-Small 1.0，也不使用早期四人数据模型。

## 固件行为

1. 将上述模型复制为固件嵌入文件 `main/models/point_direction.espdl`。
2. 方向模型预处理恢复为 128×128 RGB 和训练时的 ImageNet 均值、标准差。
3. 左右方向统一要求模型置信度至少 87%，第一名与第二名分差至少 8%。
4. 一次合格的方向推理立即输出动作 1 或 2，移除 TinyPointNet 使用的两帧方向确认和 `point_wait` 状态。
5. 保留乐鑫官方手势 Top-3 保护：`ok`、`five`、`like` 的正式结果和保护候选始终优先于方向模型。
6. 保留单手、上方控制区、Hand Detect 置信度等现有入口条件；动作冷却和必须释放后再触发的规则不变。
7. 模型仍嵌入 Flash，不从 SD 卡加载。

## 兼容性和失败处理

- 初始化时严格校验模型输入为 128×128×3，输出至少包含三个类别。
- 继续支持 INT16 输出的反量化与 softmax；模型加载或输出解析失败时只禁用动作 1/2，官方动作 3/4/5 继续运行。
- 更新启动日志和 README，明确当前模型、阈值、量化位宽与模型哈希。

## 验证

- 主机测试确认方向动作一次触发，官方动作与官方保护仍优先。
- Python 测试确认类别顺序和训练工具没有回归。
- 完整执行 ESP-IDF 构建，并核对固件确实嵌入 1,636,496 字节的指定模型。
- 实机分别测试向右指、向左指、竖大拇指、OK 和五指；重点观察大拇指与 OK 不得输出 2。

## 已知取舍

MobileNetV2-0.5 INT16 的推理时间和 Flash 占用高于 TinyPointNet INT8，但本次明确以此前实机稳定性为优先目标。若它在当前板端裁剪输入下仍出现系统性误判，下一步应采集实际运行时裁剪图重新训练，而不是继续降低阈值。

# SmartScore 均衡手势灵敏度设计

## 目标

在不改变动作编号、状态机、模型、摄像头分辨率和 AI 推理周期的前提下，降低真实手势的触发难度，同时保留基本的防误触能力。

## 参数调整

所有调整仅位于 `main/vision_config.hpp`：

- 手部检测置信度从 `0.35` 降至 `0.30`。
- 手势分类置信度从 `0.65` 降至 `0.55`。
- 控制区下边界从画面高度的 `65%` 扩大至 `85%`。
- 分类历史从最近 `6` 次改为最近 `5` 次，所需一致票数从 `4` 次改为 `3` 次。
- OK 和点赞保持时间从 `500 ms` 降至 `350 ms`；五指张开从 `800 ms` 降至 `500 ms`。
- 动作冷却时间从 `1000 ms` 降至 `800 ms`。
- 挥手最少轨迹点从 `4` 降至 `3`。
- 挥手有效时间从 `200–1200 ms` 扩大至 `150–1600 ms`。
- 挥手最小水平位移从画面宽度的 `25%` 降至 `15%`。
- 允许的最大垂直位移从画面高度的 `20%` 放宽至 `30%`。
- 相邻轨迹方向一致率从 `65%` 降至 `50%`。

## 保持不变

- AI 推理周期保持 `250 ms`，不增加 CPU 负担和看门狗风险。
- VGA 分辨率、JPEG 参数、模型和 SD 保存流程保持不变。
- 动作编号及状态约束保持不变：IDLE 仅允许挥手和 OK，RECORDING 才允许五指张开，FINISHED 才允许点赞。
- 动作触发后的重新武装逻辑保持不变，仍需手离开控制区或改变手势，避免同一动作连续触发。

## 验证

1. 静态检查所有新参数满足现有 `static_assert`。
2. 使用 ESP-IDF 5.4 完整构建。
3. 烧录后确认启动、摄像头、AI 和 SD 卡均正常。
4. 在光线充足环境测试单向挥手、OK、五指张开和点赞，并确认每个动作只输出一次对应编号。
5. 连续运行期间不得出现任务看门狗复位；少量 `FB-OVF` 只表示丢帧，不作为功能失败。

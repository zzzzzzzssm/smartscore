# SmartScore 左右指向自定义模型训练设计

## 1. 目标与范围

使用现有四名人员的数据训练一个只负责水平方向指向的三分类模型：

- `point_right`：食指在画面中指向右侧，对应动作编号 `1`。
- `point_left`：食指在画面中指向左侧，对应动作编号 `2`。
- `other`：非目标动作，不输出动作编号。

OK、五指张开和竖大拇指继续由乐鑫官方 `hand_gesture_recognition` 模型识别，分别对应动作编号 `3`、`4`、`5`。本次训练与接入不得改变照片每 3 秒保存、SD 卡、会话状态机、动作冷却以及其他无关功能。

现有数据位于 `training_data/point_dataset`，共 2960 张 640×480 JPEG：

| 人员 | other | point_left | point_right |
|---|---:|---:|---:|
| P001 | 303 | 202 | 218 |
| P002 | 357 | 213 | 210 |
| P003 | 309 | 210 | 221 |
| P004 | 308 | 202 | 207 |

全部图片能够正常解码，未发现完全重复文件。第五名人员 P005 的数据不得参与训练和调参，仅用于陌生人外部验证。

## 2. 总体方案

采用 MobileNetV2 0.5 三分类模型，输入为 128×128 RGB 手部裁剪图。训练使用 ImageNet 预训练权重，训练完成后导出固定输入形状 `1×3×128×128` 的 ONNX 模型，再使用乐鑫 ESP-PPQ 生成 ESP32-S3 专用 `.espdl` 模型。

不采用整幅 640×480 图像直接训练，避免模型学习人员面部、背景、站位和手在画面中的绝对位置。原始图片始终只读，所有裁剪图、清单和模型输出写入独立目录。

## 3. 数据预处理

### 3.1 目录与产物

新增独立 `training/` 工具目录。原始照片保持在 `training_data/point_dataset`，处理结果写入 `training_data/processed`，训练结果写入 `training_artifacts/`。`training_data/`、处理结果和中间训练产物加入 Git 忽略，避免提交人物照片和大型模型中间文件。

P005 使用独立目录：

```text
training_data/external_test/P005/
├── other/
├── point_left/
└── point_right/
```

### 3.2 手部裁剪

电脑端使用开源 MediaPipe 进行离线手部定位；MediaPipe 只作为制作训练数据的工具，不部署到 ESP32-S3。检测框扩展为包含手指和少量手腕的正方形区域，限制到图像边界后缩放为 128×128 RGB。

裁剪失败、多手画面和标签可疑图片不得静默猜测：

- 无法检测手部时，将图片路径和原因写入复核 CSV，不生成训练样本。
- `point_left` 或 `point_right` 出现多手时进入人工复核，不自动选择目标手。
- `other` 中的多手画面不拆成单手负样本，防止“两根食指相对”等画面被裁成一个看似有效的左右指向；这类图片保留用于板端误触发测试。
- 生成按类别和人员汇总的裁剪预览图，便于检查方向标签、裁剪完整度和错误检测。

### 3.3 数据增强

训练增强包含亮度、对比度、色彩、小角度旋转、轻微缩放和平移。水平翻转只能通过自定义变换执行：翻转 `point_left` 后同步改为 `point_right`，反之亦然，`other` 标签保持不变。验证和测试阶段不使用随机增强。

预处理使用与板端一致的 ImageNet 参数：RGB 像素均值 `{123.675, 116.28, 103.53}`，标准差 `{58.395, 57.12, 57.375}`。

## 4. 训练与验证

### 4.1 模型

使用 `timm` 提供的 ImageNet 预训练 MobileNetV2 0.5，将分类头替换为三个输出。训练脚本固定随机种子，保存运行配置、类别顺序、依赖版本、最佳轮次和模型校验值，使结果可以复现。

模型输出索引固定为：`0 = point_right`、`1 = point_left`、`2 = other`。训练、ONNX、ESP-PPQ 和板端包装器必须共同读取或校验这份顺序，禁止依赖目录枚举的字母排序。

训练采用两阶段迁移学习：先冻结骨干网络训练分类头，再解冻后部网络以较低学习率微调。使用类别加权或均衡采样处理 `other` 数量较多的问题，并以验证指标保存最佳权重。

### 4.2 按人员交叉验证

使用四折按人员留一验证，不随机拆散相邻照片：

1. P002～P004 训练，P001 验证。
2. P001、P003、P004 训练，P002 验证。
3. P001、P002、P004 训练，P003 验证。
4. P001～P003 训练，P004 验证。

四折完成后汇总平均值、最差人员表现和混淆矩阵。固定模型结构、轮次和阈值后，再用 P001～P004 全部有效样本训练最终模型。P005 只在最终模型确定后执行一次外部验证；如果根据 P005 结果继续调参，则后续仍需新的人员作为最终盲测对象。

### 4.3 指标与阈值

输出总体准确率、每类精确率、召回率、F1、混淆矩阵，以及 `other` 被错误判为左右动作的比例。阈值选择优先降低误触发：在交叉验证数据上选择能够将 `other` 误触发率控制在约 2% 以内的最低左右类别置信度，再比较左右召回率。

量化前后在相同验证集上比较，目标为 `.espdl` 模型相对浮点模型的准确率下降不超过 3 个百分点。未达到目标时先检查校准集、预处理一致性和量化误差，再决定是否使用混合精度或量化感知训练，不直接接受明显退化模型。

## 5. 模型导出与量化

训练产物统一写入 `training_artifacts/`：

```text
training_artifacts/
├── cross_validation/
├── final/
│   ├── point_direction.pth
│   ├── point_direction.onnx
│   ├── point_direction.espdl
│   ├── labels.json
│   ├── preprocess.json
│   └── metrics.json
└── reports/
```

ONNX 导出后使用 ONNX Runtime 与 PyTorch 对同一批输入做结果一致性检查。ESP-PPQ 校准集必须覆盖四名人员、三个类别以及不同亮度、距离和背景，目标平台明确设为 ESP32-S3。导出的 `.espdl` 包含固定的三类输出顺序，并记录文件 SHA-256。

最终 `.espdl` 嵌入 Flash rodata，不从 SD 卡加载。训练中间权重、ONNX 和报告不进入固件镜像。

## 6. 板端接入

现有乐鑫 Hand Detect 继续提供所有有效手框。板端流程为：

1. 运行官方 Hand Detect，限制检测框到图像边界并统计有效手数量。
2. 对最佳手框运行现有官方手势分类器。
3. 官方结果为 `ok`、`five` 或 `like` 时，继续按现有逻辑处理动作 `3`、`4`、`5`，不运行方向模型。
4. 官方结果为达到门槛的 `one`、只有一只有效手且手位于控制区域时，对同一手框运行自定义方向模型。
5. 自定义结果为 `point_right` 或 `point_left` 且达到交叉验证确定的阈值时，分别生成动作 `1` 或 `2`；结果为 `other` 或置信度不足时不输出。
6. 两只及以上有效手时禁止动作 `1`、`2`，但不改变官方动作 `3`、`4`、`5` 的分类和现有冷却/重新武装逻辑。

自定义模型包装器复用 ESP-DL 的 `dl::Model`、`ImagePreprocessor` 和分类后处理接口。初始化时打印模型版本、类别顺序和阈值；不得假设或改写乐鑫官方模型的类别表。

## 7. 异常处理

- 数据目录缺失、类别为空、图片损坏或标签未知时，训练前检查失败并给出明确路径。
- 手部裁剪失败率、类别数量和多手数量写入报告；不允许用整图或中心裁剪静默替代失败样本。
- 显存不足时自动降低批量大小，不改变输入尺寸和模型结构。
- ONNX 与 PyTorch 输出不一致、量化精度超出允许下降范围或 ESP-DL 操作不受支持时停止发布 `.espdl`。
- 板端自定义模型加载失败时只禁用动作 `1`、`2`，官方检测、动作 `3`～`5` 和照片保存继续工作。
- 任何推理失败不得泄漏图像缓冲区或 `camera_fb_t`。

## 8. 验证顺序与完成条件

依次完成：

1. 数据检查和裁剪预览人工确认。
2. 四折按人员交叉验证完成并生成报告。
3. P001～P004 最终浮点模型训练完成。
4. PyTorch 与 ONNX 输出一致性检查通过。
5. ESP-PPQ 量化评估通过并生成 ESP32-S3 `.espdl`。
6. ESP-IDF 完整构建通过，应用分区不溢出。
7. P005 离线验证完成。
8. P005 在开发板上分别测试向右指、向左指、其他动作、多手画面以及原有动作 `3`～`5`。
9. 串口确认动作 `1`～`5` 仍为单独一行纯数字且单次动作只输出一次。

只有当方向类别、预处理、量化配置和板端映射完全一致，且 P005 没有不可接受的 `other` 误触发时，才将模型视为可用版本。
